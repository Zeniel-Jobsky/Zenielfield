# ZeniField · 현장·매장 운영관리 플랫폼

현장 방문계획 → 실제 방문 결과 → 후속 조치를 연결하는 반응형 B2B 운영관리 웹 애플리케이션입니다.

현재 ChatGPT Sites 배포본의 소스 스냅샷입니다. **확장 플랫폼의 30명·100현장·500매장은 가상 데모 데이터**이며, 실제 직원·고객 데이터는 이 저장소에 포함되지 않습니다.

## 구현 범위

- 통합 대시보드: 조직·담당자·현장·매장·기간 필터, 현장/매장별 필요 회차와 이행률, 조직별 상세 탐색
- 현장·매장 계층형 목록, 상세 탭, 공동 담당자 배정
- 월간·주간·목록형 방문 일정, 등록·수정·취소 및 긴급 방문 결과 입력
- 방문 결과에서 후속 조치 생성, 담당자·기한·상태 관리
- 주간 활동 브리핑: 이번 주/지난주 미리보기, 조치 필요 우선 카드 3개, 검색, 주차별 타임라인 및 원본 결과 연결
- 모바일 방문 등록, 카드형 목록, 하단 메뉴
- CSV 다운로드 및 현재 조회 화면 인쇄

## 데모와 실제 운영의 구분

| 구분 | 현재 상태 |
| --- | --- |
| 확장 현장·매장 플랫폼 | 브라우저 메모리에서 작동하는 데모. 새로고침 시 초기화 |
| 기존 실제 운영 화면 | 기존 현장·방문·조치 API 및 D1 저장 구조 보존. 등록 계정 로그인 필요 |
| 주간 브리핑 | 데모 화면에서는 데모 기록, 실제 운영 화면에서는 권한 검증 후 받은 기존 저장 기록 재사용 |
| 매장·공동 담당·필요 회차 영구 저장 | DB 및 서버 계약 확장 필요 |
| AI 요약 | 미연결. 현재는 방문 목적과 활동 원문 발췌 |

현장 자체 방문과 매장 방문은 별도 대상 ID로 처리합니다. 본사 방문을 산하 매장 전체 방문으로 완료 처리하지 않습니다. 예정일이 지나도 실제 결과가 없으면 완료되지 않습니다.

## 개발 환경

- Node.js 22.13 이상, pnpm (`package.json`의 packageManager 버전 기준)
- React 19, TypeScript, Vinext/Vite, Cloudflare Workers/D1, Drizzle
- Pretendard 기반 한국어 UI와 Lucide 아이콘

```bash
pnpm install
pnpm dev
```

기본 휴대용 개발 프로필은 포트 5173을 사용합니다. Sites 관리 환경에서는 전용 미리보기/빌드 도구를 사용합니다. 실제 운영 로그인은 Sites의 신뢰된 인증 헤더와 D1 바인딩에 의존하므로 GitHub에 업로드하는 것만으로 별도 서버의 인증·운영 DB가 연결되지는 않습니다. 로컬 데이터베이스는 개발용으로 별도 준비해야 합니다.

```bash
pnpm build
```

Sites 원본의 `.openai/hosting.json`은 배포 식별자와 스토리지 바인딩 선언이며 비밀키가 아닙니다. 다른 서비스에 배포할 때는 신규 프로젝트의 인증·스토리지·환경 설정을 준비해야 합니다. 운영 인증을 임의 헤더로 대체하지 마세요.

## 검증

```bash
pnpm exec tsc --noEmit
node tests/run-briefing.mjs
node tests/run-platform.mjs
node tests/logic.mjs
node tests/ui-metrics.mjs
```

현재 113개 검증: 브리핑 32개, 플랫폼 52개, 날짜/권한 20개, UI 집계 9개. API 통합 검증은 격리된 테스트용 Workers/D1 런타임에서 `CLOUDFLARE_CF_FETCH_ENABLED=false node tests/api-flow.mjs`로 실행합니다. 실제 운영 DB에서 테스트하거나 마이그레이션하지 않습니다.

## 계산 기준

- 날짜 및 주차는 Asia/Seoul, 월요일~일요일 기준
- 브리핑 방문 건수는 실제 방문일이 있는 완료 기록 기준, ID 중복 제거
- 브리핑에서 현장·산하 매장을 묶어 보여주어도 원본 방문 유형과 실적 구분은 유지
- 미해결 이슈는 현재 상태. 과거 주차의 상태 스냅샷이 아니며 주차별 숫자를 합산하지 않음
- 신규 이슈는 등록일, 완료 조치는 완료일 기준. 등록일 미확인 건은 추정하지 않음
- 확장 플랫폼 이행률 = 완료 필요 회차 / 조회 기간에 기한이 포함된 필요 회차
- 기존 실제 운영 화면은 취소 제외 도래 계획 기준의 기존 이행률 유지

## 소스 구조

- `app/platform/`: 확장 현장·매장 데모 플랫폼 및 독립 대상/회차 계산
- `app/briefing/`: 주간 활동 집계, 실제·데모 어댑터, 카드 및 타임라인
- `app/field-app.tsx`, `app/views.tsx`: 기존 실제 운영 화면
- `app/api/data/route.ts`: 인증·권한·저장 API
- `app/chatgpt-auth.ts`: Sites 인증 헤더 및 로그인 경로
- `db/`, `drizzle/`: 기존 DB 스키마와 마이그레이션
- `tests/`: 업무 불변조건 및 집계 검증
