## 3. 도구 문제 (제품 결함 아님)

run-geo·run-seed·run-cloudflare-auth·run-cloudflare-supabase는 저장소 그대로는 실행되지 않는다. 테스트 코드가 `node_modules/.pnpm/esbuild@0.28.0/...` 경로를 고정해 불러오는데, 이 PC는 `node_modules/esbuild`(0.28.0)에 설치돼 있어 `ERR_MODULE_NOT_FOUND`가 난다.
이번 회차는 테스트 파일을 고치지 않고 임시 사본의 경로만 바꿔 실행한 뒤 사본을 지웠다. 위 표의 네 묶음 결과는 이 방식으로 얻었다.
조치 후보: 경로를 `esbuild` 패키지 이름으로 불러오게 바꾼다(별도 변경 필요, 이번 회차 미수정).

## 5. 커버리지 (계획 7절 산식)

- 계획 사례 17개 중 통과·실패로 판정한 사례: 0
- 부분 근거 있음 10, 미실행 5, 차단 1, 기준 미확정 1
- 실행 커버리지 = (통과+실패) / 적용 가능 사례 = 0 / 16 (기준 미확정 1건 제외)
- 통과율은 판정 사례가 없어 산출하지 않는다.
- 단위 검사 자체는 11개 묶음·312개 단언이 모두 통과, 실패 0건이다. 이는 계획 사례의 통과가 아니라 구현 일부의 회귀 확인이다.

## 6. 판정

- 이번 회차에서 새 결함은 발견하지 못했다. 다만 P0 사례를 판정하지 못했으므로 **P0 100% 통과 기준을 충족하지 못했고, 배포 가능 판정은 하지 않는다.**
- 미실행·차단·기준 미확정은 통과가 아니다.

## 7. 남은 작업과 필요한 것

1. **실제 화면(E, UX-01·DEMO-01·SAVE-01 등):** 브라우저 자동화(Playwright 등) 설치 또는 사람이 직접 확인이 필요하다. 도구 설치는 별도 승인 대상이다.
2. **격리 환경 서버 권한·저장 검증(D):** 5개 역할 계정과 격리 환경이 필요하다. 계정 발급·운영 쓰기는 사용자 승인 후에만 한다.
3. **GEO-01 요구 확정:** 위치 기능을 다시 켤 계획인지에 따라 사례를 폐기하거나 재작성한다.
4. **테스트 경로 수정:** 네 묶음의 esbuild 고정 경로 문제(3절)를 별도 변경으로 고친다.
5. **성능 10회 측정:** 개발 서버가 아니라 `NO_BUMP=1 npm run build` 후 `npm run preview:dist`에서 측정해야 한다(DC-PERF). 이번 회차 미실행.

이번 회차는 코드·서버 설정·운영 자원을 변경하지 않았다(빌드 산출물 `dist/` 제외).
