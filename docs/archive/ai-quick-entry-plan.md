# AI 간편등록 개발 계획 (방문결과 · 주간 브리핑)

기준: 2026-10-27. 담당자 5명, 작업 기간 2026-10-28(수)–10-29(목) 2일. 목표는 방문결과를 "메모 한 줄 + 사진"으로 등록하고, 주차별 브리핑을 AI 요약으로 받아보는 것이다. AI는 초안만 만들고, 저장은 사람이 검토 후 기존 저장 흐름으로 한다.

## 범위

| 구분 | 이번 2일 포함 | 제외(후속) |
| --- | --- | --- |
| 방문결과 | 텍스트·이미지 입력 → AI 초안 → 폼 자동 채움 → 검토 후 저장 | 사진 원본 보관(Storage), 음성 입력 |
| 부가 칼럼 | AI가 기존 필드와 신규 부가 필드를 채움, 사용자가 수정 | 관리자 화면에서 칼럼 정의 편집 |
| 후속 조치 | AI가 조치 후보(유형·내용·기한) 제안, 체크한 것만 등록 | 자동 등록 |
| 주간 브리핑 | 현장 카드별·주 전체 AI 요약 생성 버튼, 결과 캐시 | 자동 발송·알림 |
| 모드 | 데모 모드(가짜 AI 응답)와 Supabase 운영 모드 | D1 기존 화면 |

## 동작 흐름

1. 방문결과 화면 상단 **AI 간편 입력**에 메모를 쓰거나 사진(최대 3장)을 올린다.
2. 브라우저가 사진을 긴 변 1280px JPEG로 줄여 `/api/assist`로 보낸다.
3. 앱 서버([app/api/assist/server.ts](../app/api/assist/server.ts))가 로그인을 확인하고 OpenAI를 호출해 아래 JSON 초안을 받는다. 형식은 JSON schema로 강제한다. 사진은 저장하지 않는다.
4. 초안만 돌려주고 DB에는 쓰지 않는다. 저장은 기존 `/api/platform` → Edge Function 흐름 그대로다.
5. 폼이 초안으로 채워지고, AI가 채운 칸에 "AI 초안" 표시가 붙는다. 사용자가 고친 뒤 **방문 완료**로 저장한다.
6. `후속 조치 필요`이면 제안된 조치 중 체크한 항목만 기존 조치 등록 흐름으로 이어진다.

| 환경 | `OPENAI_API_KEY`, `OPENAI_MODEL` 위치 |
| --- | --- |
| 개발 (`pnpm dev`) | 로컬 `.env` |
| 배포 (Sites) | Sites runtime 환경변수, 키는 secret |

브라우저에는 키를 보내지 않는다. 기본 모델은 `gpt-6-luna`(2026-10-27 GPT-6 계열 비교에서 선정)이며 `OPENAI_MODEL`로 바꾼다. 2026-10-27 로컬에서 텍스트 메모로 초안 생성 성공(응답 200, 조치 후보 2건).

## AI 응답 계약 (수요일 11:00 확정)

```json
{
  "detail": "주요 활동 내용 (기존 필수 필드)",
  "result": "특이사항 없음 | 후속 조치 필요",
  "purpose": "현장 정기점검 | 고객사 담당자 미팅 | 근로자 관리 및 면담 | 신규 인력 투입 및 채용 | 현장 민원·문제 대응 | 기타",
  "notes": "특이사항",
  "extra": {
    "summary": "한 줄 요약 (80자 이내)",
    "category": ["인력", "시설·안전", "고객 요청", "민원", "운영"],
    "urgency": "낮음 | 보통 | 높음",
    "headcount": null
  },
  "actions": [{ "type": "인력 충원", "content": "...", "dueDate": "YYYY-MM-DD" }],
  "confidence": "low | medium | high"
}
```

- `detail`, `result`, `purpose`, `notes`는 기존 필드라 DB 변경이 없다.
- `extra`는 `zf_visits.data` JSONB에 `extra`와 `aiAssisted: true`로 저장한다. 테이블 컬럼은 추가하지 않는다. `logic.js` 검증만 넓힌다.
- 선택지 밖의 값이 오면 서버에서 버리고 빈 칸으로 둔다.

## 주간 브리핑 AI 요약

- 입력: 기존 `weeklyCards()` 결과(해당 주 완료 방문, 미해결·신규·완료 이슈). 원문 전체가 아니라 카드 데이터만 보낸다.
- 출력: 현장별 3줄 요약, 주 전체 요약(잘된 점, 위험, 다음 주 할 일).
- 저장: 신규 테이블 `zf_briefings(week_start, scope, content jsonb, source_ids, generated_by, generated_at)`. 같은 주·범위는 캐시를 보여주고 **다시 생성** 버튼으로 갱신한다.
- 화면에 "AI 요약 · 원본 방문 기준" 표시와 원본 방문 링크를 유지한다.

## 역할 분담 (5명)

개발과 병합은 1번이 맡는다. 2번과 5번은 Claude Code로 각자 맡은 화면을 만들고 1번이 리뷰 후 병합한다. 3·4번은 코드를 만지지 않고 업무 기준과 실제 입력 시험을 맡는다.

| 담당 | 강점 | 맡는 일 | 결과물 |
| --- | --- | --- | --- |
| 1 · 개발 총괄 | 개발 | AI API·단계형 입력(완료), 저장 검증(`extra`·`aiAssisted`), 브리핑 AI 요약 API·캐시, 테스트, 배포·secret 설정, 2·5번 코드 리뷰·병합 | 서버·데이터·배포 |
| 2 · 대시보드 표기 | 그래픽, 바이브코딩 | AI로 저장된 값을 대시보드·목록에 보이게: 방문기록 목록에 한 줄 요약·분류·긴급도 칸, 긴급도 "높음" 강조와 필터, 분류별 건수 카드, "AI 작성" 표시. 입력 화면 디자인은 이번 범위에서 제외 | `app/platform/views.tsx`(`VisitRecords`, `CapacityCards`, `Exceptions`) |
| 3 · 업무 기준 | CRM 업무 | 분류·긴급도·조치 유형 기준표, 부가 칼럼 확정, AI 초안 정답 판정(샘플별 맞음/틀림) | 기준표 1장, 판정표 |
| 4 · 현장 사용자 | 영업 현장 경험 | 실제 방식대로 휴대폰으로 메모·사진 입력 시험, 실제 메모 샘플 10건 작성, 불편한 점 기록 | 샘플 10건, 사용 소감 |
| 5 · 기능 개선 | 개선 의지 | 주간 브리핑 AI 요약 화면(요약 생성 버튼, 현장별 3줄 요약, 다시 생성), 요약 말투·형식 예시, 작은 기능 개편 3건 이내 | `app/briefing/`, 개선 목록 |

5번의 작은 기능 개편은 수요일 오전에 후보를 적고 1번과 3건 이내로 고른다. 화면 문구, 버튼 위치, 기본 필터처럼 저장 구조를 바꾸지 않는 것만 이번 범위에 넣는다.

3·4번은 데모 모드(기본 화면)에서 시험하므로 운영 데이터를 건드리지 않는다.

담당 미정: 촬영·개인정보 안내 문구, 1장짜리 사용 안내, 목요일 시연 진행. 제안은 4번 시연, 5번 안내 문구.

## 시작 전 결정 필요

- [x] **AI 제공자**: OpenAI. 키는 로컬 `.env`에 등록됨.
- [ ] **배포 secret**: Sites에 `OPENAI_API_KEY`(secret), `OPENAI_MODEL` 추가.
- [ ] **외부 AI 사용 승인**: README의 "외부 AI를 사용하지 않습니다" 방침이 바뀐다. 고객사·근로자 정보가 외부로 전송되는 데 대한 내부 승인이 필요하다.
- [ ] **사진 개인정보**: 얼굴·명찰·서류가 찍힐 수 있다. 촬영 가이드 문구와 "사진은 저장하지 않음" 안내 문구를 정한다.
- [ ] **비용 한도**: 사용자당 하루 호출 수(제안: 방문 초안 30회, 브리핑 10회).
- [ ] **게이트웨이 토큰**: Sites secret 교체가 먼저 끝나야 목요일 운영 통합이 가능하다.
