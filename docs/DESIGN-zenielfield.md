# ZeniField 디자인 지침

> ZeniField는 운영 현황을 빠르게 파악하고 데이터를 정확하게 처리하기 위한 관리자 사이트다. 디자인은 사용자가 **지금 무엇을 보고 있는지, 무엇을 해야 하는지, 처리 결과가 무엇인지** 알 수 있도록 돕는다.

이 문서는 DESIGN-voidx.md를 ZeniField 용도로 재구성한 독립 지침이다. 기존 Voidx 워드마크·코랄 포인트·서비스 아이콘·Cohere 소개 페이지 규칙은 계승하지 않는다. 사용자 지정 기업 컬러와 제공 로고가 브랜드 기준이며, 아래 크기·여백·UI 파생색은 ZeniField를 위한 제품 설계 기준이다. 공식 Zeniel CI 매뉴얼로 간주하지 않는다.

## 시각적 베이스 — Cohere의 절제된 정보 표현

사용자 피드백을 반영한 최우선 적용 규칙이다. 기존 문서의 색상 제안과 충돌하면 이 절을 우선한다.

- **중요도에 따라 명도 차이를 만든다.** 페이지 제목·핵심 수치·주요 식별값은 #111111, 일반 데이터·입력값은 #4b5563, 필터·레이블·보조 동작은 #626b78, 설명·메타데이터는 #6b7280을 사용한다. 모든 항목명과 수치를 진하게 만들거나 기업색을 일반 글자색으로 사용하지 않는다.
- **Cohere 참고 자료의 흰 표면, 얇은 구분선, 정돈된 여백, 낮은 시각적 장식**을 베이스로 한다. 대형 마케팅 제목·사진·히어로는 관리자 화면에 이식하지 않는다.
- Green은 최우선 채움 버튼, 현재 메뉴의 표시선, 선택 탭 밑줄, 업무상 필요한 핵심 강조에만 사용한다. 일반 링크와 보조 버튼은 검정/회색이며 밑줄·경계·배치로 조작 가능성을 전달한다.
- 기본 아이콘·필터 값·테이블 본문·담당자 이름·안내 문구는 중립색이다. 모든 수치와 아이콘을 녹색으로 칠하지 않는다.
- 성공·경고·오류는 의미 전달이 필요한 값과 상태 배지에서만 사용한다. 배지 밖의 일반 설명까지 같은 색으로 확장하지 않는다.
- 입력창은 식별 가능한 얇은 경계와 6px 모서리, 업무 패널은 8px 모서리를 사용한다. 대형 미디어용 둥근 카드 규칙보다 업무 밀도와 읽기 순서를 우선한다.

### 정보의 강약과 페이지 리듬

**옅은 UI 위에 중요한 정보가 진하게 보이도록 설계한다.** 컨트롤의 테두리와 설명이 핵심 데이터보다 먼저 눈에 들어오지 않게 한다. 화면 전체의 투명도를 낮추지 말고 역할별 색상 토큰을 적용한다.

| 시각적 단계 | 적용 대상 | 표현 |
|---|---|---|
| 가장 강함 | 페이지·섹션 제목, KPI 값, 주요 식별값 | #111111, 600; 크기와 여백으로 읽는 순서 형성 |
| 기본 | 테이블 일반 데이터, 사용자가 입력한 값 | #4b5563, 400; 오류 확인에 필요한 실제 값은 흐리게 만들지 않음 |
| 보조 | 셀렉트 값, 필드 레이블, 일반 메뉴, 보조 버튼 | #626b78, 400–500; 제목과 같은 검정·굵기로 강조하지 않음 |
| 설명 | 단위, 집계 기준, 날짜·수정 시각, 안내 문구 | #6b7280, 400; 읽을 수 있는 대비 유지 |
| 구조 | 패널 외곽선, 헤더·행 구분선 | #e7ebf0, 1px; 배경과 여백으로 그룹 구분을 보완 |
| 조작 경계 | 셀렉트·입력·검색창·보조 버튼 | 기본 #d5dbe3 → hover #aeb8c4; 포커스에서 명확하게 강조 |

- 테이블은 모든 셀을 굵게 만들지 않는다. 핵심 이름·합계·결정에 필요한 수치만 진하게 표시한다. 날짜·단위·설명은 보조 단계로 둔다.
- 대시보드는 **진한 제목 → 옅은 필터 → 큰 핵심 수치 → 보조 설명 → 얇은 구분선**으로 시선이 이어지게 한다. 필터 묶음이 가장 강한 시각 요소가 되지 않게 한다.
- Green은 주요 행동·선택 상태·업무상 중요한 강조에 제한한다. 정보의 강약을 모두 Green 농도 차이로 표현하지 않는다.
- 셀렉트 화살표는 #7b8794, 16px, 오른쪽 여백 12px, 세로 중앙 정렬이다. 오른쪽 내부 패딩은 40px을 확보하고, 짧은 컨트롤도 텍스트가 화살표 아래로 들어가지 않게 너비를 조정한다.
- 입력한 값과 선택 가능한 기본값을 disabled처럼 보이게 만들지 않는다. 실제 disabled 상태는 별도로 구분한다.
- 연한 기본 외곽선만으로 조작 가능성을 전달하지 않는다. 상시 레이블·셀렉트 화살표·입력 표면을 함께 제공한다. 체크박스·라디오와 필수 상태 표식은 식별 가능한 진한 경계를 유지한다.
- 키보드 포커스는 #1d4ed8의 2px 이상 링, 오류는 #b42318의 메시지와 경계로 명확하게 표현한다. 기본 UI를 옅게 만드는 규칙을 포커스·오류·선택·중요 알림에 적용하지 않는다.

## 1. 핵심 원칙

1. **업무가 먼저다.** 첫 화면에서 주요 현황, 처리할 항목, 다음 행동을 파악할 수 있어야 한다.
2. **데이터를 읽기 쉽게 만든다.** 일관된 정렬·단위·날짜·상태 이름으로 비교 부담을 줄인다.
3. **실수를 예방하고 복구를 돕는다.** 저장 상태, 검증 오류, 변경 범위, 삭제 영향을 명확히 표시한다.
4. **반복 작업을 짧게 만든다.** 검색 조건 유지, 키보드 이동, 일괄 처리, 목록 복귀를 우선한다.
5. **브랜드는 절제한다.** 로고와 작은 Green 강조로 정체성을 전달한다. 업무 화면의 넓은 면적은 중립색을 사용한다.
6. **색만으로 정보를 전달하지 않는다.** 선택·성공·오류를 문구, 아이콘, 형태와 함께 표시한다.

기본 모드는 밝은 화면이다. 다크 모드는 별도 토큰과 검증이 준비될 때 도입한다. 장식용 히어로, 대형 인사 문구, 배경 사진, 그라디언트, 글로우, 3D 아이콘, 반복 모션은 운영 화면에서 사용하지 않는다.

## 2. 브랜드와 로고

### 로고 원본

- 제공 파일 `zeniel_logo1_trans_type1.png`를 그대로 사용한다. 확인된 이미지 크기는 264 × 107px이다.
- 원본 종횡비와 색을 유지한다. CSS 필터 재색상, 임의 재제작, 글꼴로 로고 흉내 내기, 늘이기, 기울이기, 그림자 추가를 금지한다.
- 투명 이미지의 내부 여백까지 포함하여 배치하며 자동으로 잘라내지 않는다. 실제 보이는 로고 크기는 화면에서 확인한다.
- 원본보다 큰 표시가 필요하면 승인된 고해상도 또는 벡터 원본을 사용한다. 작은 PNG를 확대해 선명도를 잃게 하지 않는다.
- 축소형 심볼·반전형·파비콘은 승인된 별도 자산이 있을 때만 사용한다. 전체 로고에서 임의로 심볼을 잘라 만들지 않는다.

### 제품 내 배치 기준

| 위치 | 기준 |
|---|---|
| PC 앱 셸 좌상단 | 흰 배경에 원본 표시, 이미지 박스 높이 32–40px, 너비 자동 |
| 제품명 | `ZeniField`를 UI 폰트 16px/600으로 별도 표시; 로고와 최소 12px 간격 |
| 로고 보호 여백 | 이미지 박스 외곽에서 최소 8px; 공식 CI 기준이 제공되면 해당 기준 우선 |
| 좁은 화면·접힌 내비게이션 | 전체 로고를 과도하게 줄이지 않고 제품명과 메뉴 버튼 사용; 전체 로고는 열린 메뉴 안에서 제공 |
| 로그인 | 원본 로고와 제품명 사용; 소개용 대형 브랜드 패널은 생략 |

로고는 앱 셸에서 한 번만 노출하는 것을 기본으로 한다. 카드, 차트, 테이블마다 반복하지 않는다. 로고 홈 링크에는 `aria-label="ZeniField 대시보드"`를 제공하고 내부 이미지는 `alt=""`로 중복 낭독을 피한다. 단독 이미지는 `alt="Zeniel"`을 사용한다. 편집 중 홈 이동에도 미저장 변경 보호를 적용한다.

## 3. 색상 체계

### 브랜드색과 기능색 구분

| 토큰 | 값 | 사용 |
|---|---|---|
| brand-green | `#009c64` | 원본 기업색, 활성 메뉴 표시선, 작은 강조 그래픽 |
| brand-black / text-primary | `#111111` | 제목·핵심 수치·주요 식별값 |
| text-body | `#4b5563` | 일반 데이터·실제 입력값 |
| action-primary | `#007a4d` | 흰 글자를 사용하는 주요 버튼, 텍스트 링크 |
| action-hover | `#00663f` | 주요 버튼 hover |
| action-pressed | `#005234` | 주요 버튼 pressed |
| brand-subtle | `#e8f5ee` | 활성 메뉴·선택 행의 옅은 배경 |
| canvas | `#f5f6f8` | 앱 전체 배경 |
| surface | `#ffffff` | 테이블·폼·패널 |
| surface-muted | `#f3f4f6` | 테이블 헤더·보조 영역 |
| text-secondary | `#626b78` | 셀렉트 값·레이블·일반 메뉴·보조 버튼 |
| text-muted | `#6b7280` | 설명·날짜·메타데이터; 핵심 정보에는 사용하지 않음 |
| border | `#e7ebf0` | 비조작 패널·행 구분 |
| control-border | `#d5dbe3` | 셀렉트·입력·검색창·보조 버튼의 기본 외곽선 |
| control-border-hover | `#aeb8c4` | 조작 요소 hover 경계 |
| control-icon | `#7b8794` | 펼침 화살표·조작 식별 표식 |
| focus | `#1d4ed8` | 키보드 포커스 |
| danger / danger-subtle | `#b42318` / `#fef3f2` | 오류·삭제·실패 |
| warning / warning-subtle | `#8a4b00` / `#fff7e6` | 주의·지연·검토 필요 |
| success / success-subtle | `#166534` / `#edf7ee` | 저장 성공·처리 완료 |
| info / info-subtle | `#1d4ed8` / `#eff6ff` | 안내·진행 중 |

**원본 Green과 업무용 Green은 다른 역할이다.** `#009c64`와 흰색의 계산 대비는 약 3.54:1이므로 14px 흰 글자 버튼에는 사용하지 않는다. 주요 버튼은 `#007a4d` + 흰색(약 5.40:1)을 기본으로 한다. 기업색이 직접 필요한 배지는 `#009c64` + `#111111` 조합을 사용할 수 있으나 의미 문구를 반드시 붙인다. 로고 원본 색은 변경하지 않는다.

위 수치는 sRGB 색상값에 대한 계산이며 실제 화면의 투명도·중첩·상태까지 검증한 결과는 아니다. 일반 텍스트 대비 4.5:1 이상, 큰 글자와 조작 요소의 식별 경계·상태 표시 대비 3:1 이상을 제품 검수 목표로 한다.

- Green을 모든 버튼·수치·차트에 사용하지 않는다. 한 작업 영역에서 최우선 행동만 채움 버튼으로 강조한다.
- 성공과 선택은 같은 녹색 계열이라도 `완료` 문구/체크 아이콘과 선택 표시선/체크박스로 구분한다.
- 빨강은 실제 오류·위험 의미에 사용한다. 감소 수치가 반드시 나쁜 것은 아니다. 증감과 좋고 나쁨을 분리한다.
- Black은 글자 중심으로 사용한다. 사이드바 전체를 검정으로 채우는 방식은 기본안이 아니다.

## 4. 타이포그래피·간격·표면

기본 폰트 스택은 `"Pretendard", -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`다. Pretendard 자산이 없는 경우 설치되어 있다고 가정하지 말고 시스템 폰트로 표시한다. 별도 도입 시 배포 라이선스와 한글 렌더링을 확인한다.

| 역할 | 크기 / 행간 | 굵기 |
|---|---|---|
| 페이지 제목 | 24 / 32px | 600 |
| 섹션 제목 | 18 / 26px | 600 |
| 패널 제목 | 16 / 24px | 600 |
| 본문·입력·테이블·버튼 | 14 / 22px | 400, 버튼·레이블 500 |
| 보조 설명 | 13 / 20px | 400 |
| 제한적인 메타데이터 | 12 / 18px | 400 |
| KPI 숫자 | 28 / 36px | 600 |

- 주요 데이터와 필수 안내를 12px로 줄여 맞추지 않는다. 모바일 입력은 16px을 기본으로 한다.
- 한글 자간은 기본 0. 대문자·과도한 음수 자간·얇은 300 굵기를 업무 정보에 사용하지 않는다.
- 수치 비교에는 `font-variant-numeric: tabular-nums`를 사용한다. 본문 전체에 고정폭 글꼴을 적용하지 않는다.
- 간격은 4px 단위: 4 / 8 / 12 / 16 / 24 / 32. 페이지 패딩 24px, 모바일 16px, 패널 내부 16–24px.
- 모서리는 입력·버튼 6px, 패널·대화상자 8px, 상태 배지 4px. 일반 버튼을 알약형으로 만들지 않는다.
- 카드에는 기본 그림자를 넣지 않는다. 경계선과 배경으로 영역을 구분한다. 메뉴·팝오버·대화상자에만 약한 그림자를 허용한다.
- 패널 안의 모든 필드를 다시 카드로 감싸지 않는다. 제목·간격·구분선으로 그룹을 나눈다.

## 5. 앱 셸과 탐색

- 데스크톱 헤더 높이 64px, 사이드바 너비 240px, 접힌 상태 64px을 기본으로 한다.
- 상단에는 제품 식별, 현재 조직/사업장 범위, 알림, 사용자 메뉴를 둔다. 조직/사업장 개념은 실제 서비스에 존재할 때만 사용한다.
- 사이드바는 업무 기준으로 구성한다. 예: 대시보드 / 운영 데이터 / 보고서 / 설정. 이 명칭은 예시이며 실제 권한·업무 구조에 맞춘다.
- 메뉴 깊이는 기본 2단계 이내. 현재 메뉴는 옅은 Green 배경 + 3px 표시선 + 글자 굵기로 표시하고 `aria-current="page"`를 제공한다.
- 페이지 헤더는 경로(필요 시), 제목, 한 줄 설명, 주요 행동 순서로 구성한다.
- 목록·대시보드는 가용 폭을 활용한다. 긴 편집 폼은 최대 960px을 기본으로 하여 시선 이동을 줄인다.
- 고정 헤더·저장 바는 콘텐츠와 포커스된 요소를 가리지 않도록 여백과 스크롤 위치를 보정한다.
- 내부 업무 화면에 마케팅 푸터·홍보 배너·대형 환영 영역을 넣지 않는다.

## 6. 대시보드

권장 정보 순서는 **조회 범위 → 핵심 지표 → 처리 필요 항목 → 추이/상세 현황**이다.

1. 상단에 기간·대상 범위와 마지막 갱신 시각을 표시한다. 모든 카드가 같은 범위를 따르는지 명확히 한다.
2. KPI는 기본 3–5개. 각 지표에 이름·값·단위·집계 기준을 제공한다. 비교 수치는 `전월 동기간 대비`처럼 기준을 밝힌다.
3. 미처리·오류·마감 임박 등 행동이 필요한 목록을 눈에 띄는 위치에 둔다. 과도한 빨간색 배경 대신 건수·기한·바로가기 중심으로 구성한다.
4. KPI나 차트에서 목록으로 이동하면 기간·대상·상태 조건을 이어받는다.
5. 갱신 실패 시 기존 값을 0으로 바꾸지 않는다. `갱신 실패 · 마지막 성공 14:20`처럼 데이터의 신뢰 상태를 표시한다.

### 차트

- 추이는 선, 항목 비교는 막대를 기본으로 한다. 정확한 값 비교에는 표를 함께 제공한다.
- 첫 시리즈에 업무용 Green, 다른 시리즈에 구분 가능한 보조색을 사용한다. 시리즈 의미와 색을 화면 간 고정한다.
- 축·단위·범례·툴팁에 충분한 레이블을 제공한다. 색 외에도 선 형태·마커·직접 레이블로 구별한다.
- 막대 차트의 수량 축은 원칙적으로 0에서 시작한다. 다른 축 범위가 필요한 경우 명확히 표시한다.
- 3D 차트, 장식용 게이지, 불필요한 도넛 차트, 자동 카운트업을 사용하지 않는다.
- 차트 hover만으로 데이터를 제공하지 않는다. 키보드 접근 가능한 상세 값이나 데이터 표를 제공한다.
- 실제 데이터가 없는 시안에는 `예시 데이터`를 표시한다. 가짜 수치를 실제 운영값처럼 표시하지 않는다.

## 7. 목록·테이블·검색

### 기본 구조

`페이지 제목 + 등록 버튼 → 검색/필터 → 결과 건수 + 보조 도구 → 테이블 → 페이지 이동`

| 항목 | 기준 |
|---|---|
| 기본 행 높이 | 44px; 여러 줄 내용은 자연스럽게 확장 |
| 밀집 모드 | 반복 조회에 한해 36px 선택 가능; 기본 글자 14px 유지 |
| 터치 환경 | 조작 영역 44 × 44px 이상, 행 높이 48px 이상 권장 |
| 헤더 | 40–44px, 14px/500, 옅은 중립 배경 |
| 셀 여백 | 좌우 12–16px |
| 정렬 | 텍스트 왼쪽, 숫자·금액 오른쪽, 짧은 상태 가운데 가능 |
| 행 상태 | hover 중립 배경; 선택 옅은 Green + 체크박스 |
| 기본 페이지 크기 | 25행; 50/100행 선택은 성능에 맞춰 제공 |

- 식별자·이름·상태 등 핵심 열을 우선한다. 긴 텍스트는 줄바꿈 또는 상세 보기로 전체 내용을 확인할 수 있게 한다.
- 핵심 식별값을 말줄임만으로 숨기지 않는다. 툴팁만을 유일한 확인 수단으로 사용하지 않는다.
- 헤더 정렬 버튼과 방향을 표시한다. `<th scope="col">` 및 `aria-sort`를 적용한다.
- 기본은 의미론적 HTML table이다. 스프레드시트식 편집이 실제 필요한 경우에만 키보드 모델을 갖춘 grid를 사용한다.
- 넓은 표는 표 영역에서 가로 스크롤한다. 필요 시 식별 열을 고정하되 좁은 화면을 과도하게 가리지 않게 한다.
- 행 전체 클릭에 의존하지 않고 이름 링크 또는 `상세 보기` 버튼을 제공한다. 선택 체크박스와 행 동작의 클릭 영역을 분리한다.
- 데이터 0, 미입력, 해당 없음, 불러오기 실패를 구분한다. 빈 숫자 칸에 임의의 0을 채우지 않는다.

### 검색과 필터

- 일반 검색은 검색어 + `조회` 버튼을 기본으로 한다. 입력 중 자동 반영과 버튼 반영을 같은 영역에서 혼용하지 않는다.
- 검색 입력의 Enter는 조회한다. 한글 조합 중 Enter는 조합 확정으로 처리하여 조기 검색을 막는다.
- 기본 필터는 자주 쓰는 3–5개만 노출하고 나머지는 `상세 조건`에서 제공한다.
- 적용 중인 조건, 결과 건수, `조건 초기화`를 표시한다. 입력 중 조건과 실제 적용 조건을 구분한다.
- 검색·정렬·페이지 크기·스크롤 위치를 상세 화면에서 돌아올 때 복원한다. 조건 변경 시 첫 페이지로 이동한다.
- 날짜 범위는 시작일·종료일 포함 여부, 업무 시간대, 기본 조회 기간을 명시한다.
- 조건 저장 시 개인정보를 URL이나 공용 저장소에 노출하지 않는다.

### 일괄 처리와 내보내기

- 선택 시에만 일괄 작업 바를 표시하고 `선택 12건`처럼 범위를 설명한다.
- 현재 페이지 전체 선택과 전체 검색 결과 선택을 구분한다. 다른 페이지 선택의 유지 여부를 명확히 한다.
- 삭제·승인 등 중요한 작업은 대상 수와 영향 범위를 확인한다. 일부 실패 시 성공/실패 수와 실패 행의 재시도 방법을 제공한다.
- 내보내기는 `현재 검색 결과 128건` 등 대상을 명시한다. 진행·완료·실패·다운로드 만료를 안내하고 권한에 맞는 열만 제공한다.

## 8. 운영 데이터 입력·수정

### 폼 구성

- 레이블은 입력창 위에 항상 표시한다. placeholder는 예시이며 레이블을 대체하지 않는다.
- 필수 항목은 `필수` 문구 또는 설명된 별표로 표시한다. 입력 형식·단위·허용 범위는 입력 전에 안내한다.
- 관련 항목을 3–6개 정도씩 의미 단위로 묶는다. 단일 열을 기본으로 하고 짧고 관련된 항목만 2열로 배치한다.
- 입력창 높이 40px, 모바일 44px 이상. 긴 메모는 충분한 높이의 textarea를 제공한다.
- 선택지가 적으면 라디오, 많으면 검색 가능한 선택기를 사용한다. 필수 선택을 임의의 첫 값으로 채워 실수를 유발하지 않는다.
- 전화번호·사번·우편번호 같은 식별값은 숫자로 계산하지 않는다. 앞자리 0을 보존한다.
- 금액은 표시용 천 단위 구분과 실제 저장값을 구분하고 음수·소수·반올림 규칙을 정의한다.
- 읽기 전용 정보는 일반 텍스트 또는 명확한 read-only 스타일로 표시한다. 비활성 입력창을 과도하게 사용하지 않는다.

### 검증과 오류

- 입력 전부터 오류를 띄우지 않는다. 필드를 벗어나거나 제출할 때 검사하고 수정 후 해제한다.
- 오류는 해당 필드 아래에 원인과 해결 방법을 함께 표시한다. 예: `종료일은 시작일 이후로 선택해 주세요.`
- 제출 오류가 여러 개면 상단 요약과 각 필드 연결을 제공한다. 첫 오류로 포커스를 이동한다.
- 오류 필드에 `aria-invalid`, 설명에 `aria-describedby`를 연결한다.
- 서버 오류 후 입력값을 보존한다. 토스트만 띄우고 입력창을 초기화하지 않는다.
- 첨부 파일은 허용 형식·용량·개수, 업로드 진행률·실패·재시도를 제공한다.

### 저장과 이탈

- 기본은 명시적 `저장`이다. 자동 저장과 명시적 저장을 설명 없이 혼합하지 않는다.
- 주요 행동은 `저장`, 보조 행동은 `취소` 또는 `목록으로`다. 제출·승인과 단순 저장은 다른 이름과 흐름을 사용한다.
- 저장 중에는 버튼 문구를 `저장 중…`으로 바꾸고 중복 제출을 막는다. 서버 성공을 확인하기 전 완료로 표시하지 않는다.
- 성공 시 저장 시각·결과를 안내한다. 목록 복귀 또는 편집 유지 정책을 화면 유형별로 일관되게 정한다.
- 변경이 있을 때만 이탈 확인을 표시한다. `계속 작성`과 `변경 내용 버리고 나가기`처럼 결과가 분명한 문구를 사용한다.
- 동시 수정 충돌은 다른 사용자의 최신 데이터가 있음을 알리고 비교·새로 불러오기·입력값 보존을 제공한다. 조용히 덮어쓰지 않는다.
- 긴 입력에서 임시 저장을 제공한다면 저장 위치·보관 기간·복구 범위를 정의한다. 민감한 정보를 브라우저에 무조건 저장하지 않는다.

## 9. 상세 조회와 변경 이력

- 상단에 항목명·식별자·현재 상태를 표시한다. 필드 순서는 입력 폼과 대응시킨다.
- 기본 정보·운영 정보·변경 이력처럼 읽는 목적에 따라 그룹화한다. 단순 데이터 조회를 입력창 모음처럼 표현하지 않는다.
- 주요 수정 버튼은 상단에 배치한다. 삭제는 주요 저장/수정 동작과 시각적으로 분리한다.
- 변경 이력에는 변경 시각·작업자·항목·변경 전후 값을 권한 범위 안에서 제공한다.
- 목록 복귀 시 필터·정렬·페이지·스크롤 위치가 유지되어야 한다.

## 10. 공통 컴포넌트와 상태

| 컴포넌트 | 적용 기준 |
|---|---|
| 주요 버튼 | 업무용 Green 채움 + 흰 글자; 한 작업 영역의 최우선 행동 |
| 보조 버튼 | 흰 배경 + 식별 가능한 경계 + 진한 글자 |
| 위험 버튼 | danger 사용; 삭제 대상과 영향을 확인한 뒤 실행 |
| 텍스트 링크 | 업무용 Green + 밑줄 등 링크 단서; hover에만 의존하지 않음 |
| 아이콘 버튼 | 16–20px 단일 선 아이콘, 접근 가능한 이름, 44px 터치 영역 |
| 상태 배지 | 12–13px, 옅은 배경 + 진한 글자 + 상태명; 자체를 버튼처럼 보이게 하지 않음 |
| 툴팁 | 보충 설명용; 필수 안내를 툴팁에만 넣지 않음 |
| 토스트 | 짧은 성공 안내; 실패·복구 행동은 지속되는 인라인 안내 병행 |
| 모달 | 짧은 확인·단순 입력, 기본 480–640px; 복잡한 편집은 별도 페이지 |
| 드로어 | 목록 맥락을 유지하는 빠른 상세; 전체 화면 링크 제공 |

### 상태별 행동

- **로딩:** 최종 구조에 맞춘 스켈레톤 또는 진행 표시. 기존 검색 결과 갱신 시 화면을 불필요하게 비우지 않는다.
- **초기 데이터 없음:** 무엇을 등록할 수 있는지 설명하고 권한이 있으면 등록 버튼을 제공한다.
- **검색 결과 없음:** 적용 조건을 보여주고 조건 해제·변경을 돕는다.
- **실패:** 원인 범위, 재시도 방법, 기존 입력/데이터 유지 여부를 안내한다.
- **부분 실패:** 실패한 영역만 표시하고 성공한 결과는 유지한다.
- **읽기 전용/권한 없음:** 이유와 가능한 행동을 설명한다. 권한 제어는 서버에서도 수행한다.
- **세션 만료:** 다시 로그인할 방법과 작성 내용의 보존 가능 여부를 알린다. 무조건 복구된다고 약속하지 않는다.

버튼·입력·선택기에는 default / hover / focus / active / disabled / loading / error 중 해당 상태를 정의한다. 비활성 버튼은 이유를 인접 문구로 설명한다. 클릭할 수 없는 버튼에 달린 hover 툴팁에만 이유를 넣지 않는다.

## 11. 반응형·키보드·접근성

| 폭 | 기본 동작 |
|---|---|
| 1280px 이상 | 펼친 사이드바, 업무 밀도에 맞춘 다열 대시보드 |
| 1024–1279px | 접힌 사이드바 기본, 차트·카드 열 수 축소 |
| 768–1023px | 메뉴 드로어, 1–2열 대시보드, 폼은 가급적 1열 |
| 768px 미만 | 1열, 필터 접기, 터치 영역 확대, 표 내부 가로 스크롤 |

- 모바일에서도 핵심 조회·입력·저장이 가능해야 한다. 핵심 열을 무조건 숨기는 방식으로 폭 문제를 해결하지 않는다.
- 행 비교가 중요한 표는 표 형태를 유지한다. 단일 항목 탐색이 주목적인 경우에만 모바일 요약 목록을 병행한다.
- 키보드만으로 메뉴 → 필터 → 결과 → 행 동작 → 페이지 이동을 수행할 수 있게 한다.
- 모든 조작 요소에 2px 이상의 명확한 포커스 표시와 2px 간격을 제공한다. 상태 변화로 포커스를 잃지 않게 한다.
- 모달은 제목 연결, 초기 포커스, 내부 포커스 순환, 닫힌 뒤 원래 위치 복원을 제공한다. 미저장 변경이 있으면 Escape에도 이탈 보호를 적용한다.
- 숨겨진 드로어·메뉴가 Tab 순서에 남지 않도록 한다. 본문 바로가기와 의미 있는 heading 순서를 제공한다.
- 200% 확대에서 조작과 정보가 손실되지 않도록 확인한다. 좁은 폭에서도 페이지 전체가 불필요하게 가로 스크롤되지 않도록 한다.
- 상태 안내는 적절한 live region으로 제공하되 자동 갱신 수치를 계속 낭독하지 않는다.
- 모션은 기본 120–180ms의 짧은 상태 전환에만 사용한다. reduced-motion에서는 불필요한 전환을 제거한다.

## 12. 운영 문구와 데이터 표기

- 버튼은 구체적인 동사로 쓴다: `조회`, `등록`, `저장`, `승인`, `선택 항목 삭제`. 모호한 `확인`은 줄인다.
- 같은 상태에 다른 이름을 섞지 않는다. 상태 정의·전환 가능 행동·권한을 함께 관리한다.
- 표시 날짜 기본은 `YYYY-MM-DD`, 시각은 `YYYY-MM-DD HH:mm`. 한국 운영 기준은 Asia/Seoul이며 다른 시간대 데이터는 변환 기준을 명시한다.
- 숫자는 `1,234`, 금액은 `1,234,000원`, 비율은 정해진 소수 자릿수를 일관되게 적용한다. 표 헤더에 공통 단위를 명시해 반복을 줄일 수 있다.
- 빈 값은 의미에 따라 `미입력`·`해당 없음`·`집계 중`으로 구분한다.
- 오류 문구는 사용자 행동을 돕는다: `저장하지 못했습니다. 입력 내용은 유지됩니다. 다시 시도해 주세요.` 단, 실제 보존 동작이 있을 때만 이 문구를 사용한다.
- 개인정보 마스킹·열람·다운로드는 역할에 맞춘다. 가려진 값을 CSS로만 숨기지 않는다.

## 14. 화면별 적용 템플릿

### A. 대시보드

- 제목 `운영 현황` + 기준 기간/대상 + 마지막 갱신 시각
- 핵심 KPI 3–5개
- 처리 필요 목록 + 상태·기한·바로가기
- 주요 추이 차트 + 데이터 표/상세 목록 연결

### B. 운영 데이터 목록

- 제목 + `등록`
- 검색어 / 기간 / 상태 + `조회` / `초기화`
- 결과 건수 + 열 설정 / 내보내기
- 식별값 / 항목명 / 업무 핵심값 / 상태 / 수정 시각 / 상세
- 페이지 이동, 선택 시에만 일괄 작업

### C. 입력·수정

- 제목 + 항목 식별값 + 현재 상태
- 기본 정보 → 운영 정보 → 첨부·메모
- 필드 안내와 오류, 변경 여부
- `취소` + `저장`, 저장 중·성공·실패 상태

### D. 상세 조회

- 이름·식별자·상태 + `수정`
- 관련 정보 그룹
- 변경 이력
- 조건이 유지되는 `목록으로`

위 업무명과 구성은 설계 예시다. 실제 기능·권한·집계 항목이 확정되기 전 구현된 기능처럼 안내하지 않는다.

## 16. 구현 요청 시 사용할 요약 지침

> ZeniField 관리자 UI를 구현한다. DESIGN-zenielfield.md를 디자인 기준으로 사용한다. 기업색은 Zeniel Green #009c64와 Zeniel Black #111111이며, 제공된 로고 원본을 변형하지 않는다. 기본은 밝은 중립 배경·흰 업무 표면·14px 한글 UI·명확한 표와 입력 구조다. 흰 글자 주요 버튼에는 접근성을 고려한 #007a4d를 사용한다. 대형 히어로·장식 그래픽·과도한 둥근 카드·불필요한 애니메이션을 넣지 않는다. 일반 컨트롤·테두리는 옅게, 제목·핵심 수치·주요 식별값은 진하게 표현해 페이지의 리듬을 만든다. 포커스·오류·선택 상태는 명확하게 유지한다. 대시보드의 조회 범위, 테이블의 조건 유지, 입력 검증, 저장 상태, 오류 복구, 키보드 사용을 시각 장식보다 우선한다. 실제 기능과 데이터 구조를 확인하고 없는 업무·권한·수치를 임의로 만들지 않는다.
