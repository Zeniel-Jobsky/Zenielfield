# ZeniField 디자인 지침

2026-10-29 · ZeniField 프로젝트 · `현재 UI v2.0` `차트 설계`

---

> 💡 **밝은 업무 화면, 분명한 강조** — 넓은 면적은 흰색과 흰색에 가까운 중립색으로 유지한다. 중요한 행동·선택 상태·방문 이행률에 딥그린을 집중하고, 데이터는 숫자·정렬·여백으로 읽게 한다.

이 문서는 ZeniField의 독립 제품 지침이다. `DESIGN-cohere.md`에서 절제된 색상·타이포·구분선 원칙을 참고하되 외부 서비스의 이름·로고·마케팅 화면을 복제하지 않는다. 공식 Zeniel CI 매뉴얼을 대신하지 않는다. 사용자의 최신 디자인 요청을 우선하며, 이전 버전의 베이지 표면·밝은 기업색 버튼·반복 카드 규칙은 아래 현재 기준으로 대체한다.

**문서 상태:** 1–5절과 13절의 현재 토큰은 소스의 구현값을 기준으로 한다. 6절의 차트와 차트 전용 토큰은 향후 구현을 위한 설계 사양이다. 나머지 운영 UX 원칙과 검수 항목은 구현 여부를 확인할 기준이며, 전부 구현되었다는 뜻이 아니다. 이번 개정은 문서 갱신이며 차트 컴포넌트를 추가하지 않는다.

## 1. 핵심 원칙

1. **정확한 업무 단위를 먼저 정한다.** 대상 수 `개`, 방문 기록 `건`, 필요·완료 `회차`, 비율 `%`를 혼합하지 않는다.
2. **흰 공간이 기본이다.** 넓은 베이지·세이지 배경, 모든 지표를 감싼 카드, 반복 장식 아이콘을 추가하지 않는다.
3. **강조는 한눈에 구분된다.** 주요 행동·현재 선택·대표 이행률에는 딥그린과 흰 글자를 사용한다. 일반 데이터까지 녹색으로 만들지 않는다.
4. **크기와 간격으로 읽는 순서를 만든다.** 제목 → 조회 범위 → 핵심 수치 → 추이·업무 목록 → 세부 근거로 이어지게 한다.
5. **상태색은 의미가 있을 때만 쓴다.** 지연·기한 초과는 빨강, 계획 미등록·주의는 앰버로 표시하되 문구를 반드시 함께 제공한다.
6. **데이터를 숨기지 않는다.** 차트·요약 옆에서 원본 목록과 집계 기준에 접근할 수 있어야 한다. 색이나 hover만으로 필수 정보를 제공하지 않는다.

밝은 모드가 기준이다. 다크 모드는 별도 검증 후 도입한다. 그라디언트·글로우·3D·불필요한 도넛·자동 카운트업·반복 모션은 사용하지 않는다. 예외는 독려 안내(10-A)의 한 번 재생 트윈뿐이다.

## 2. 브랜드와 로고

- 제품명은 **ZeniField**, 기업명은 **Zeniel/제니엘**로 유지한다. Cohere·voidx 이름과 워드마크를 제품에 이식하지 않는다.
- 현재 메뉴와 운영 진입 화면에는 제공된 [`zenifield_logo.png`](../public/brand/zenifield_logo.png)를 표시한다. 376×138 원본의 종횡비·색상·흰 배경·내부 여백을 보존한다. 표시 폭은 펼친 데스크톱 메뉴 180px, 모바일 메뉴 158px, 운영 진입 화면 188px이다.
- 접힌 데스크톱 메뉴의 `ZF`는 좁은 공간에서 쓰는 텍스트 대체 표시다. 로고 이미지에서 글자나 심볼을 잘라내거나 재색상하지 않는다.
- 원본 기업색 참고값 `#009c64`와 현재 UI의 딥그린 `#003c33`을 구분한다. 전자는 로고·CI 확인용이고, 후자는 현재 제품의 행동·선택 색이다.
- 현재 메뉴는 딥그린 바탕·흰 글자로만 표시한다. 예전의 6px 코랄 점 `#ff7759`는 알림 빨간 점과 헷갈려 2026-10-28에 없앴다. 메뉴 안의 점·빨간 표식은 쓰지 않고, 빨간 점은 상단 알림 종에만 쓴다. 메뉴 옆 숫자는 중립 회색 알약(현재 메뉴에서는 흰 반투명)이다.
- 로고·제품명 홈 링크에는 접근 가능한 이름을 제공한다. 편집 중 이동은 미저장 변경 보호 기준을 따른다.

### 표면과 강조의 배분

- 필터와 표 머리글은 `#f8faf9`를 사용한다. 베이지 `#eeece7`·`#f4f3ef`를 넓은 기본 배경으로 다시 사용하지 않는다.
- 차트 영역은 흰색이다. 구분을 위해 차트 전체를 회색·녹색 카드로 채우지 않는다.
- 현재 대시보드의 대표 강조는 **방문 이행률**이다. 다른 지표는 흰 바탕·큰 숫자로 두고, 이행률만 딥그린 채움으로 표시한다.
- 현장·매장 탭의 하단선과 바로 아래 핵심 지표 셀 사이는 PC·태블릿 16px, 모바일 12px 띄운다. 지표 셀은 흰 바탕과 상단 1px 구조선으로 구분하며 왼쪽 컬러 테두리를 두지 않는다. 방문 이행률만 딥그린 채움으로 강조한다. 모바일의 데모·운영 전환 버튼 문구는 필요한 경우 줄바꿈하여 화면 너비를 넘지 않게 한다.
- 현재 메뉴·선택된 주차·선택된 입력 방식·주요 행동은 딥그린 채움 + 흰 글자를 사용한다. 일반 탭은 진한 글자 + 2px 밑줄로 선택을 표현한다.
- 일반 텍스트 4.5:1 이상, 차트의 의미 있는 선·마커와 상태·포커스 표시 3:1 이상을 목표로 실제 조합을 검수한다. 옅은 구조선에는 이 수치만을 강제하지 않으며 필수 조작 경계·데이터 표식을 대신하게 하지 않는다.

sRGB 단색 계산 기준: 흰색/딥그린 약 12.40:1, 강조 보조 글자/딥그린 약 9.73:1, 보조 글자/흰색 약 6.15:1, 설명 글자/보조 표면 약 4.80:1이다. 투명도·작은 글자·실제 렌더링 검수는 별도로 한다.

## 4. 타이포그래피·간격·표면

**아이콘 배율 (2026-10-29):** 4단계만 쓴다 — `--zf-icon-xs` 14px(11–13px 글자 옆·링크 화살표·표 안) · `--zf-icon-sm` 16px(본문·버튼·입력·칩·탭) · `--zf-icon-md` 20px(메뉴·상단 동작·아이콘 버튼) · `--zf-icon-lg` 24px(빈 상태). 선 굵기 1.75 고정(`svg.lucide`), 글자와 함께 있으면 기준선 정렬. 컴포넌트 `size`는 14·16·20·24만, CSS에서 아이콘 크기를 px로 다시 정하지 않고 토큰을 쓴다. 이 배율은 일반 UI 아이콘(Lucide)에 적용한다. 메시지를 설명하는 장식 SVG는 10-A의 44/56px·64캔버스 기준을 별도로 따른다.

한글 기본 스택은 `Pretendard, -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`다. Pretendard가 설치·제공되어 있다고 가정하지 않는다. 숫자·짧은 영문에는 로컬 `Space Grotesk` Regular를 사용하고, 한글은 기본 스택으로 폴백한다. 현재 제공 자산은 400 굵기이므로 숫자를 임의의 합성 굵기로 만들지 않는다.

| 페이지 제목 | 30px / 1.3, 400, 자간 -0.8px | 26px / 1.3 |
| 섹션·차트 제목 | 기본 17px / 1.4, 500 · 운영 현황 H2는 18px / 1.4, 600 | 기본 16px · 운영 현황는 17px / 1.4, 600 |

- **AI 브리핑 점진 공개 (2026-10-28):** 기본 화면은 상태 칩 + `요약` + 첫 번째 `제안`만 보여 준다. 요약 본문은 PC·태블릿 20px/모바일 18px, 제안 본문 17px/16px, 행간 1.7로 읽기 쉽게 강조한다. 요약·제안은 PC 2열(요약이 더 넓음), 태블릿·모바일 1열이며 테두리 카드 대신 여백으로 묶는다. `보고 내용에서 보이는 것 · 더 보기`와 `브리핑 자세히 보기`는 흰 바탕·중립 경계·6px 모서리·44px 이상 조작 영역의 가벼운 보조 버튼이다. hover는 기존 옅은 중립 표면, focus는 공통 포커스 링, 펼침 시 상태 문구와 방향 아이콘이 바뀐다. 보고 내용은 기본 접힘 → 클릭하면 현장별 이름과 주제명만 → 각 현장의 `더 보기`에서 주제 요약·상태·근거를 공개한다. **보고 목록 안 구분선은 현장 사이에만** 두며 주제·근거 목록·상세 텍스트에는 선을 두지 않는다. 여러 현장에 걸친 주제와 근거는 공통 정보임을 표시하고 임의로 특정 현장의 근거로 바꾸지 않는다. 대상 없는 주제도 `현장 미지정`으로 보존한다. `브리핑 자세히 보기`에는 흐름·잘 되는 점·챙길 곳·상황·추가 판단·다음에 볼 것·격려 문구·증감 칩·작성 근거를 담고, 기본 제안을 중복하지 않는다. 상세 제목·목록은 선 대신 16–24px 여백을 쓴다. AI 실패 이유·규칙 대체·확신 낮음은 접지 않고 알린다. 조건·역할·기간이 바뀌면 모두 접힌 상태로 돌아가고, 각 버튼은 `aria-expanded`·`aria-controls`로 해당 콘텐츠와 연결한다. 숨긴 내용은 Tab 순서에서 제외하며 펼침·접기 시 버튼 포커스를 유지한다. 주차별 AI 브리핑에도 같은 컴포넌트 기준을 적용한다. 생성 요청·응답·집계·원본 데이터는 바꾸지 않는다.

AI 브리핑·차트 분석 묶음·사업장 진단·주간 브리핑·방문 우선 확인은 각각 독립된 그룹으로 읽히게 그룹 사이 32px(모바일 24px)를 둔다. 차트 6개의 배치·순서는 유지하고 열 사이 24px, 행 사이 32px(태블릿 32px, 모바일 24px)로 구분한다. 그룹 안 제목→내용은 16px(모바일 12px), 구조선→제목은 20px(모바일 16px)로 둔다. 제목과 본문은 왼쪽 기준선을 맞추며 긴 제목·우측 도구는 줄바꿈한다. 흰 표면·상단 1px 구조선·모서리 0·그림자 없음은 유지한다. 값은 `app/zeniel.css`의 대시보드 공통 토큰으로 관리하고 다른 화면의 H2에는 적용하지 않는다.
- 잡매니저 홈(2026-10-29): 오늘 업무 → 독려 숫자 칸 + 먼저 가 보면 좋은 곳(한 덩어리, 다음 방문은 이 목록만) → 오늘·이번 주 방문 표 → 미완료 조치 → 핵심 지표 → AI 요약 → 차트 → 우선 확인 현장 → 주간 요약. 별도 독려 띠·'이번 주 진행' 차트·코치 문장 목록을 두지 않는다(같은 숫자·대상 반복 금지).

| `--zf-chart-area` | `rgb(0 60 51 / .06)` | 선택적으로 쓰는 단일 면적 보조 채움; 필수 데이터 전달은 진한 선으로 수행 |

- 일반 비교는 기본 1–2개 시리즈, 최대 3개다. 네 상태를 보여주는 회차 구성만 네 상태색을 허용한다. 그 이상은 필터·별도 패널로 나눈다.
- 팀·파트 비교의 모든 막대는 기본 같은 딥그린이다. 조직마다 다른 무지개색을 배정하지 않는다. 선택 항목만 외곽선·직접 레이블로 추가 강조한다.
- 현장·매장 시리즈 색과 완료·예정 상태색이 우연히 같아도 범례에는 전체 의미를 쓴다. `완료`를 `현장`으로 오해할 수 있는 중첩 범례를 만들지 않는다.
- 이전 기간은 중립색 점선으로 표시한다. 현장/매장과 이전 기간까지 네 선을 겹치지 말고 비교 대상 탭 또는 분리 패널을 사용한다.
- 목표는 값이 실제 설정된 경우에만 1.5px 중립 점선 + `목표 80%` 같은 레이블로 표시한다. 임의 목표·기준선을 만들지 않는다.
- 비교값이 작거나 비활성화되어도 단순 opacity로 필수 선을 읽을 수 없게 만들지 않는다. 범례에서 숨김 여부를 텍스트·토글 상태로 제공한다.
- 흰색 기준 위 진한 시리즈 색들의 계산 대비는 3:1 이상이어야 한다. 서로 인접한 누적 조각은 흰색 2px 간격과 레이블·표 대체를 사용하며 색 구별만으로 정확한 비교를 요구하지 않는다.
- 붉은색·앰버는 경고 의미가 없는 일반 증감이나 항목 순번에 사용하지 않는다. 증가·감소의 좋고 나쁨은 지표 정의에 따라 별도 판단한다.

### 6.5 축·선·막대·범례·툴팁

- **선:** 기본 2px, 선택 3px. 기본 마커는 숨기고 선택·키보드 포커스·단일 점에는 지름 6–8px 마커를 표시한다. 선 구분은 색 + 실선/점선 + 범례 표식으로 제공한다.
- **막대:** 세로 막대 폭 16–24px, 가로 막대 두께 12–16px, 끝 모서리 2px. 그룹 내 간격 4–6px, 그룹 간 16px 이상을 확보한다. 작은 값의 길이를 임의로 늘리지 않는다. 0값은 `0건` 레이블/표에서 확인한다.
- **누적 막대:** 각 조각의 원래 비중을 유지한다. 2px 분리선 때문에 작은 값이 사라지면 직접 레이블·표로 보완한다. 좁은 조각 안에 흰 글자를 강제로 넣지 않는다.
- **수량 축:** 막대는 0에서 시작하며 건수·회차는 정수 눈금만 쓴다. 4–5개 주요 눈금, 모바일 3–4개를 기본으로 한다. 작은 범위에 같은 정수 눈금을 반복하지 않는다.
- **비율 축:** 0–100% 고정이 기본이다. 이행률은 정수 %, 비교는 `+5%`가 아닌 `+5%p`로 표현한다. 차트 내부 계산은 원래 분자·분모를 유지한다.
- **현장·매장 운영 상태 (2026-10-29):** 막대와 표시 비율의 분모는 모두 조회 범위의 운영 중 해당 유형 대상 수다. 막대 너비는 반올림 전 `상태별 대상 수 / 전체 대상 수 × 100`, 표시는 정수 반올림 %. 최대 항목을 100%로 확대하지 않는다. 0–100% 기준과 `대상 수`·`비율` 열을 표시하고 `51개`와 `48%`처럼 단위·열·간격으로 분리한다. 0건 막대는 길이0, 전체 대상0이면 산정 비율 대신 빈 상태 안내를 표시한다. 상태 분류·조회 조건·원본 목록 이동은 유지한다. 사용자 요청에 따라 이 차트의 행은 밀집 목록 예외로 최소24px·상하 패딩2px·행간6px(시작점 간30px)이며, 글자는12px 이상을 유지한다. 행 전체 클릭·키보드 포커스는 유지하고 내용이 길면 높이는 자연스럽게 늘어난다. 공통 ChartPanel은 접기 버튼 없이 제목·범례·본문을 항상 표시한다.
- **격자:** 수평선만 1px `chart-grid`; 세로 격자·바깥 박스·모든 눈금의 굵은 선은 생략한다. 0 기준선은 보조 글자색 1px로 구분한다.
- **날짜 축:** 짧은 표시는 `10.19–10.25`, 주차 제목·툴팁은 `10월 4주차 · 2026-10-19–2026-10-25`처럼 실제 범위를 함께 쓴다. 모바일은 3–4개 눈금만 노출하되 모든 데이터는 남긴다.
- **범례:** 기본 플롯 위 왼쪽, 12px. 표식 폭 12–16px, 표식과 글자 6px, 항목 간 16px. 좁으면 줄바꿈한다. 선 시리즈는 선 형태·마커도 표시한다. 직접 레이블로 자명한 단일 시리즈 범례는 생략할 수 있다.
- **툴팁:** 흰 바탕 + 1px 입력 경계 + 6px 모서리, 내부 12px, 행 간 8px, 그림자 없음. 날짜·항목·각 시리즈 이름·정확한 값·단위를 표시한다. 흰 플롯과의 분리는 경계로 처리한다. 화면 밖으로 나가지 않게 위치를 보정한다.
- **숫자:** `1,234건`, `완료 69 / 필요 175회차`, `39%`처럼 단위를 명시한다. 작은 축에는 `1천` 등 축약을 허용하되 툴팁·표에는 정확한 값을 표시한다.
- **강조:** 선택 마커/외곽선 + 값 표시를 우선한다. 차트 전체를 어둡게 덮거나 미선택 시리즈를 거의 투명하게 만들지 않는다. 지연 상태는 색과 `지연` 문구로 강조한다.

### 6.6 집계 기준과 데이터 신뢰

1. **같은 조회 범위:** 대시보드는 기간·조직·담당·현장·매장 및 현장/매장 탭을 차트에도 전달한다. 브리핑은 현재의 활동 검색·현장 모아보기·방문자 조건을 반영한다. 별도 조건이 있으면 차트 제목 아래에 명시한다. 공동 담당은 대상을 중복 합산할 이유가 아니다.
2. **필요 회차:** 현재 `aggregate()` 기준을 재사용한다. 조회 기간에 **기한이 들어오는 회차**가 분모이며 각 방문은 최대 한 회차만 충족한다. 추가 완료 방문·수동 관리 대상·취소 기록은 필요 회차 구성에 임의로 더하지 않는다. 필요 회차가 0이면 비율은 `— / 산정 대상 없음`이다.
3. **실제 활동:** 현재 `weekStats()`처럼 완료 상태·유효한 실제 방문일·현재 날짜 이내의 방문 기록을 ID로 중복 제거하여 집계한다. 계획일로 실제 활동 추이를 채우거나 미래 실적을 만들지 않는다. 현장 방문과 산하 매장 방문은 분리한다.
4. **주차:** Asia/Seoul, 월요일–일요일 기준이다. 조회 경계의 주차는 해당 기간과 겹치는 날짜만 집계하고 `부분 주차 · 집계 10.01–10.04`처럼 표시한다. 진행 중 주차는 `집계 중` 표식을 제공한다. 불완전한 주와 완전한 주를 동등한 증감 비교로 해석하지 않는다.
5. **회차 주차와 이행 시점:** 회차를 기한 주차로 묶으면 제목을 `기한 주차별 현재 이행 상태`로 쓴다. 현재 상태를 나눈 값을 `당시 주간 이행률 추이`로 표시하지 않는다. 과거 시점의 상태·이행률 차트는 시점별 스냅샷이나 이력 기반 재구성이 확보된 뒤 도입한다.
6. **이슈:** 신규는 등록일, 완료는 완료일을 사용한다. 날짜 미확인 기록은 해당 발생 집계에서 제외하고 제외 건수를 알린다. **현재 미해결은 현재 상태**이므로 매주 같은 값을 과거 잔여량처럼 그리거나 주차별 값을 합산하지 않는다. 과거 주차 종료 시점의 미해결 수는 별도 이력 없이는 제공하지 않는다.
7. **0과 결측:** 정상 집계된 활동 0은 `0`, 미수집·권한 부족·불러오기 실패는 결측/오류로 구분한다. 선 차트 결측은 선을 끊고 `데이터 없음`으로 설명한다. 로딩·실패에 0선이나 가짜 막대를 그리지 않는다.
8. **비교와 비율:** 평균 이행률은 조직별 반올림 비율의 단순 평균이 아니라 `완료 회차 합 / 필요 회차 합`으로 계산한다. 이전 기간 0 또는 비교 범위 불일치면 증감률을 억지로 계산하지 않는다. 필요할 때 `비교 불가`와 이유를 쓴다.
9. **실제·데모 구분:** 데모에는 `데모 데이터`, 시안에는 `예시 데이터`를 계속 표시한다. Supabase 운영에 시안용 수치를 넣지 않는다. 차트와 원본 목록의 합계가 맞는지 확인하고, 다르면 단위·코호트 차이를 설명한다.

### 6.7 상호작용·상태·접근성

- 마우스 hover, 키보드 포커스, 터치 선택에서 같은 값에 접근한다. 터치에는 44px 이상 선택 영역/인접 컨트롤을 제공하며 툴팁은 Escape 또는 닫기 조작으로 해제할 수 있게 한다.
- 차트에는 접근 가능한 제목과 기간·단위·핵심 결과의 짧은 요약을 제공한다. 색·모양만으로 전체 내용을 이해하도록 요구하지 않는다.
- `데이터 표 보기`로 동일 집계의 표를 제공한다. 날짜·항목명·값·단위·제외/결측 상태를 포함한다. 긴 시리즈에서는 모든 점을 Tab 정지점으로 만들지 말고 날짜 이동 컨트롤 또는 표로 접근한다.
- 범례 토글이 있다면 이름·현재 표시 상태·키보드 동작을 제공한다. `aria-pressed` 등 실제 컨트롤 의미를 사용하고, 시리즈를 숨겨도 원래 분모를 조용히 바꾸지 않는다.
- 막대/점 클릭이 원본 조회로 연결되면 기간·대상·상태를 이어받는다. 클릭 가능한 표식에만 포인터와 명확한 이름을 제공한다. 단순 조회에 새 데이터를 저장하지 않는다.
- 로딩에는 최종 높이의 옅은 중립 스켈레톤을 사용한다. 빈 데이터는 등록/조건 변경 안내, 실패는 재시도, 갱신 실패는 마지막 성공 데이터와 시각을 보여준다. 상위 KPI와 차트의 갱신 상태가 다르면 이를 알린다.
- 데이터 진입 애니메이션과 숫자 카운트업은 기본 끔이다(차트·지표). 독려 안내(10-A)만 값이 바뀐 순간 한 번 재생을 허용한다. 선택 피드백만 120–160ms까지 허용하고 `prefers-reduced-motion`에서는 제거한다. 자동 갱신 수치를 계속 낭독하지 않는다.
- 인쇄·내보내기에는 범례·기간·단위·집계 기준과 출처를 포함한다. 툴팁에만 있던 필수 데이터는 표로 함께 제공한다.

## 7. 목록·테이블·검색

### 기본 구조

- 후속 조치 목록의 전체·미처리·조치 예정·처리 중·보류·완료·기한 초과 탭에서 같은 목록 정렬을 제공한다. 잡매니저별은 현재 탭 건수가 많은 순이며 동률은 이름·담당자 ID, 같은 담당자는 초과 일수 내림차순이다. 초과 일수는 미완료는 오늘, 완료는 실제 완료일 기준이며 음수는 0일로 표시 기준을 통일한다. 완료일이 없으면 초과 여부를 추정하지 않고 0일로 취급한다. 초과 일수 동률은 처리기한·등록일·ID순이다.


`페이지 제목 + 등록 버튼 → 검색/필터 → 결과 건수 + 보조 도구 → 테이블 → 페이지 이동`

| 항목 | 기준 |
|---|---|
| 기본 행 높이 | 56px, 13px 본문; 여러 줄 내용은 자연스럽게 확장 |
| 밀집 모드 | 반복 조회에 한해 44px 선택 가능; 본문은 최소 13px 유지 |
| 터치 환경 | 조작 영역 44 × 44px 이상, 행 높이 48px 이상 권장 |
| 헤더 | 44px 이상, 12px/400, 옅은 중립 배경 |
| 셀 여백 | 좌우 12–16px |
| 정렬 | 텍스트 왼쪽, 숫자·금액 오른쪽, 짧은 상태 가운데 가능 |
| 행 상태 | hover 중립 배경; 선택 옅은 Green + 체크박스 |
| 기본 페이지 크기 | 화면별 유지: 현장 10행, 필요 회차 15행, 방문 기록 20행; 크기 변경 기능은 도입 시 성능에 맞춰 제공 |

- 식별자·이름·상태 등 핵심 열을 우선한다. 긴 텍스트는 줄바꿈 또는 상세 보기로 전체 내용을 확인할 수 있게 한다.
- 핵심 식별값을 말줄임만으로 숨기지 않는다. 툴팁만을 유일한 확인 수단으로 사용하지 않는다.
- 헤더 정렬 버튼과 방향을 표시한다. `<th scope="col">` 및 `aria-sort`를 적용한다.
- 기본은 의미론적 HTML table이다. 스프레드시트식 편집이 실제 필요한 경우에만 키보드 모델을 갖춘 grid를 사용한다.
- 넓은 표는 표 영역에서 가로 스크롤한다. 필요 시 식별 열을 고정하되 좁은 화면을 과도하게 가리지 않게 한다.
- 행 전체 클릭에 의존하지 않고 이름 링크 또는 `상세 보기` 버튼을 제공한다. 선택 체크박스와 행 동작의 클릭 영역을 분리한다.
- 데이터 0, 미입력, 해당 없음, 불러오기 실패를 구분한다. 빈 숫자 칸에 임의의 0을 채우지 않는다.

### 검색과 필터

- 운영 현황·방문 기록은 태블릿·데스크톱에서 조직 필터를 펼쳐 첫 줄에, 기간 선택·초기화를 둘째 줄 왼쪽에 배치한다. 최신 기간 선택 팝오버와 모바일 접이식 범위 선택은 유지한다. 아래 공통 배치의 화면별 예외다.

**역할별 조회 범위 필터 (2026-10-29):** 기본값은 본인 범위 전체로 이미 선택된 상태라 따로 드러내지 않는다. 필터 자리에는 현재 범위 버튼 하나(`리테일운영팀 전체 ⌄`, 직접 고르면 마지막으로 고른 값, 44px)만 두고, 누르거나 터치할 때만 바꿀 수 있는 단계의 선택 상자가 아래 한 줄로 펼쳐진다. 바꿀 수 있는 단계: 사업부장·관리자 = 사업부·팀·파트·잡매니저·현장·매장, 팀장 = 파트·잡매니저·현장·매장, 파트장 = 잡매니저·현장·매장, 잡매니저 = 현장·매장. 선택지가 하나뿐인 단계는 숨기고, 바꿀 단계가 하나도 없으면 버튼도 없다. 범위를 설명하는 별도 줄·고정값 칩 같은 중복 표기를 두지 않는다. 조회 조건 칩에는 직접 고른 값만 나온다.

**조회 기간 선택 (2026-10-29):** `[◀ 기간 이름 ▶]` 하나로 둔다. 화살표는 지금 단위(하루·주·달, 그 외는 같은 길이)만큼 앞뒤로 옮긴다. 이름은 범위를 말한다(`오늘 10.29(목)`, `이번 주 10.26–11.01`, `2026년 10월`, 그 외 `10.01–10.31`). 가운데를 누르면 빠른 선택(오늘·이번 주·지난주·이번 달·지난달·최근 4주·최근 3개월, 각 칸에 실제 날짜 표기, 선택된 칸 딥그린 테두리+체크)과 `직접 선택`(시작일·종료일 + 적용, 최대 1년)이 열린다. 데스크톱은 기간 버튼 아래 팝오버(320px), 모바일은 화면 아래 시트. 날짜 입력 두 칸은 `직접 선택`에서만 보인다. Esc·바깥 누르기로 닫고 포커스는 기간 버튼으로 돌아간다. 배치: 데스크톱 `[범위 버튼] ··· [◀ 기간 ▶][초기화]` 한 줄, 태블릿 `[범위][초기화]` + `[◀ 기간 ▶]`, 모바일 `[범위][초기화]` + 전체 폭 `[◀ 기간 ▶]`. 운영 화면 필터 배치 규칙은 `app/platform/styles.css` 끝의 한 블록에만 둔다.

**통합 검색 자동완성 (2026-10-29):** 상단·모바일 검색창 공통. 한 글자부터 담당자·현장·매장을 최대 8개 추천(초성 검색 포함, 앞부분 일치 우선), 줄마다 종류 아이콘·이름·`담당자 · 팀 · 파트` 같은 보조 줄, 44px. 고르면 그 범위로 바로 좁히고 검색어는 비운다(담당자를 고를 수 없는 잡매니저는 이름 검색). ↑↓·Enter·Esc, combobox/listbox 역할. 후보는 권한 범위 안 대상과 그 담당자만.

**상태 이름표 (2026-10-29):** 회차 상태는 `방문 완료`·`방문 예정`·`방문 지연`·`계획 미등록`(짧게 완료·예정·지연·계획 미등록), 대상 상태는 여기에 `이력 미확인`·`필요 방문 없음`(옛 `정상 관리`)을 더한다. 주차별 브리핑 사업장 칩은 판정이 있으면 `판정 위험`·`판정 주의`, 없으면 사실(`기한 초과 n건`·`진행 중 조치 n건`·`방문 지연`·`열린 조치 없음`). `정상` 같은 판정 단어를 코드가 붙이지 않는다(DC-JUDGMENT). 이름표는 `app/platform/model.ts`의 `SLOT_LABEL`·`SLOT_SHORT`·`NO_HISTORY`·`NO_REQUIRED`에서만 가져온다.

**일정 잡기 전 빈 날 확인 (2026-10-29):** AI 방문 일정 등록 맨 앞 `00 방문할 날 고르기`. 오늘부터 7일을 칩 한 줄(`오늘 10.29 · 1건`, `금 10.30 · 비어 있음`, 48px 이상, 좁으면 가로 스크롤)로 보이고, 누르면 AI 입력 앞에 날짜가 들어간다. 필요 회차 기간은 딥그린 테두리, 고른 날은 외곽선. 방문 목록 전체는 방문 일정 화면 달력에서 보며 여기서 반복하지 않는다. **초안(AI·데모)은 빈칸만 채우고 사람이 고른 값이 우선**: 고른 날짜·일정 잡기로 정해진 대상·이미 고른 대상·목적은 덮어쓰지 않는다. 외부 캘린더 연동은 하지 않는다.

**일정 미리 찾기·후보 예측 (2026-10-29):** 대상이 정해지면 7일 칩 대신 사실 한 줄(`필요 방문 10.31까지 (2일 남음)` · `마지막 방문 09.01` · `주로 10:00 (n회)` · 이미 잡힌 일정은 주의색)과 후보 날짜 칩(최대 5개, 날짜순)을 보인다. 후보는 필요 회차 기간 안(없으면 앞으로 2주), 이미 이 대상 일정이 있는 날 제외, 꼬리표가 붙는 날만: `비어 있음` · `같은 지역 n건` · `마감 전 마지막 빈 날`(잘리지 않게 남김). 시간은 이 대상에 주로 간 시간, 그날 겹치면 마지막 일정 1시간 뒤(18시까지), 오늘 후보는 지금 시각 이후 정각만(18시가 지나면 오늘 제외). 점수로 순위를 매기지 않는다(DC-JUDGMENT). 후보를 누르면 날짜·시간·필요 회차 연결이 바로 채워지고 AI 없이 검토·저장할 수 있다. 계산은 `app/platform/schedule.ts`.

- 일반 검색은 검색어 + `조회` 버튼을 기본으로 한다. 입력 중 자동 반영과 버튼 반영을 같은 영역에서 혼용하지 않는다.
- 검색 입력의 Enter는 조회한다. 한글 조합 중 Enter는 조합 확정으로 처리하여 조기 검색을 막는다.
- 기본 필터는 자주 쓰는 3–5개만 노출하고 나머지는 `상세 조건`에서 제공한다.
- 적용 중인 조건, 결과 건수, `조건 초기화`를 표시한다. 입력 중 조건과 실제 적용 조건을 구분한다.
- 검색·정렬·페이지 크기·스크롤 위치를 상세 화면에서 돌아올 때 복원한다. 조건 변경 시 첫 페이지로 이동한다.
- 날짜 범위는 시작일·종료일 포함 여부, 업무 시간대, 기본 조회 기간을 명시한다.
- 조건 저장 시 개인정보를 URL이나 공용 저장소에 노출하지 않는다.

### 일괄 처리와 내보내기

- 선택 시에만 일괄 작업 바를 표시하고 `선택 12건`처럼 범위를 설명한다.
- 현재 페이지 전체 선택과 전체 검색 결과 선택을 구분한다. 다른 페이지 선택의 유지 여부를 명확히 한다.
- 삭제·승인 등 중요한 작업은 대상 수와 영향 범위를 확인한다. 일부 실패 시 성공/실패 수와 실패 행의 재시도 방법을 제공한다.
- 내보내기는 `현재 검색 결과 128건` 등 대상을 명시한다. 진행·완료·실패·다운로드 만료를 안내하고 권한에 맞는 열만 제공한다.

## 8. 운영 데이터 입력·수정

> **등록 화면 (2026-10-28):** 방문 등록은 AI 입력이 기본이다. 안내 줄 오른쪽에 `직접 입력`/`AI 입력` 전환 링크를 아이콘 + 4px 간격으로 둔다. 레이블과 값은 붙여 쓰지 않고 6–10px 간격을 둔다. 계획 자동 연결은 오늘 기준 ±14일 안의 미완료 계획만 대상으로 하고, 연결 대상을 화면에 보여 주며 `계획 외로 저장`으로 바꿀 수 있게 한다.

> **GPS 위치 기능 중지 (2026-10-28):** 방문 등록의 `GPS로 지점 자동 선택`·`현재 위치 기록`과 현장·매장 마스터의 `현재 위치로 좌표 입력` 버튼을 표시하지 않는다(`app/platform/geo.tsx` `GPS_ENABLED=false`). 대상은 직접 선택한다. 다시 켜려면 값을 `true`로 바꾼다.
>
> **위치 검색 중지 (2026-10-28):** 현장·매장 마스터의 매장·주소 검색과 위도·경도 입력 칸도 표시하지 않는다(`GEO_SEARCH_ENABLED=false`). 기존 좌표는 숨은 값으로 그대로 보존한다. `/api/geo`는 외부 지도 API(Kakao)를 부르지 않고 410을 돌려주며, Kakao 키는 쓰지 않는다(폐기).

**AI로 정리하기 (2026-10-28 재배치):** 직접 입력 방문 결과에서 `특이사항` 바로 아래 한 줄: 보조 버튼 `✨ AI로 문장 정리` + 회색 12px 안내 "위 활동 내용·특이사항을 다듬어 제안합니다. 사실은 그대로 두고, 반영한 칸만 기록됩니다." 제목을 따로 두지 않는다(버튼과 중복). 쓴 다음에 정리하는 순서라 입력칸 위가 아니라 아래에 둔다. 누르면 같은 자리에 옅은 정보 표면으로 바뀌는 칸만 `현재/제안` + 체크, `선택한 칸 반영`(딥그린)·`제안 닫기`. 반영 후 `AI 정리 반영됨 · 저장 시 기록` 배지 + `되돌리기`. "고칠 곳이 없습니다"·"먼저 입력하세요" 같은 안내는 회색 12px 한 줄(빨간 오류 상자 금지), 빨간 상자는 실제 실패에만. 모바일은 버튼 전체 폭 44px.

**AI 종합 판정 (2026-10-28):** 방문 결과(직접 입력·AI 입력) 저장 시 같은 기준으로 판정한다. 첫 `저장`을 누르면 그 대상의 이전 보고·연결 조치(등록·기한·완료일)와 이번 보고를 타임라인으로 보내 판정을 받고, 저장 버튼 바로 위 판정 블록에 보여 준다: 수준 칩(정상=딥그린 `#003c33` / 관찰=예정색 `#516e8a` / 주의=`#8a4b00` 배경 `--zf-warning-soft` / 위험=`#b42318`) + 판단 한 문장 + 이슈 목록(유형·심각도·흐름 신규/지속/악화/해결, 12px). 입력자는 수준을 고를 수 있다(select, 44px). 안내 "판정을 확인하고 다시 저장을 누르세요"는 회색. 내용(목적·상세·특이사항·결과·방문일)을 바꾸면 판정을 지우고 다음 저장 때 다시 판정한다. AI 실패·데모는 이유를 주의색 한 줄로 알리고 판정 없이(미판정) 저장할 수 있다. 화면이 문장을 해석해 판정을 만들지 않는다. 백필(`scripts/judge-reports.mjs`)과 입력은 같은 지시문·타임라인 형식(`app/platform/judgment.ts` `buildJudgeInput`)을 쓴다.

**AI 연결 실패 안내 (2026-10-28):** AI 입력·일정 등록·AI 정리에서 AI를 쓸 수 없으면 빨간 오류 상자 대신 입력칸 아래 주의 표면(`#fdf4e7` 바탕, `#8a4b00` 글자, 6px 모서리) 한 줄로 `AI 연결이 안 돼(이유) 입력한 낱말로 간단 정리했습니다. 내용을 꼭 확인하세요.`를 보이고 초안은 그대로 채운다. 빨간 오류 상자는 입력 형식 오류처럼 사용자가 고칠 수 있는 경우에만 쓴다.

### 폼 구성

- 레이블은 입력창 위에 항상 표시한다. placeholder는 예시이며 레이블을 대체하지 않는다.
- 필수 항목은 `필수` 문구 또는 설명된 별표로 표시한다. 입력 형식·단위·허용 범위는 입력 전에 안내한다.
- 관련 항목을 3–6개 정도씩 의미 단위로 묶는다. 단일 열을 기본으로 하고 짧고 관련된 항목만 2열로 배치한다.
- 입력창 높이 42px, 모바일 44px 이상. 긴 메모는 충분한 높이의 textarea를 제공한다.
- 선택지가 적으면 라디오, 많으면 검색 가능한 선택기를 사용한다. 필수 선택을 임의의 첫 값으로 채워 실수를 유발하지 않는다.
- 전화번호·사번·우편번호 같은 식별값은 숫자로 계산하지 않는다. 앞자리 0을 보존한다.
- 금액은 표시용 천 단위 구분과 실제 저장값을 구분하고 음수·소수·반올림 규칙을 정의한다.
- 읽기 전용 정보는 일반 텍스트 또는 명확한 read-only 스타일로 표시한다. 비활성 입력창을 과도하게 사용하지 않는다.

### 검증과 오류

- 입력 전부터 오류를 띄우지 않는다. 필드를 벗어나거나 제출할 때 검사하고 수정 후 해제한다.
- 오류는 해당 필드 아래에 원인과 해결 방법을 함께 표시한다. 예: `종료일은 시작일 이후로 선택해 주세요.`
- 제출 오류가 여러 개면 상단 요약과 각 필드 연결을 제공한다. 첫 오류로 포커스를 이동한다.
- 오류 필드에 `aria-invalid`, 설명에 `aria-describedby`를 연결한다.
- 서버 오류 후 입력값을 보존한다. 토스트만 띄우고 입력창을 초기화하지 않는다.
- 첨부 파일은 허용 형식·용량·개수, 업로드 진행률·실패·재시도를 제공한다.

### 저장과 이탈

- 기본은 명시적 `저장`이다. 자동 저장과 명시적 저장을 설명 없이 혼합하지 않는다.
- 주요 행동은 `저장`, 보조 행동은 `취소` 또는 `목록으로`다. 제출·승인과 단순 저장은 다른 이름과 흐름을 사용한다.
- 저장 중에는 버튼 문구를 `저장 중…`으로 바꾸고 중복 제출을 막는다. 서버 성공을 확인하기 전 완료로 표시하지 않는다.
- 성공 시 저장 시각·결과를 안내한다. 목록 복귀 또는 편집 유지 정책을 화면 유형별로 일관되게 정한다.
- 변경이 있을 때만 이탈 확인을 표시한다. `계속 작성`과 `변경 내용 버리고 나가기`처럼 결과가 분명한 문구를 사용한다.
- 동시 수정 충돌은 다른 사용자의 최신 데이터가 있음을 알리고 비교·새로 불러오기·입력값 보존을 제공한다. 조용히 덮어쓰지 않는다.
- 긴 입력에서 임시 저장을 제공한다면 저장 위치·보관 기간·복구 범위를 정의한다. 민감한 정보를 브라우저에 무조건 저장하지 않는다.

## 9. 상세 조회와 변경 이력

### 9.1 상세페이지의 정보 위계·점진 공개 (2026-10-29)

주차별 활동 요약에 우선 적용하고, 긴 상세페이지를 새로 만들거나 수정할 때 같은 기준으로 다듬는다.

- **큰 구분은 구분선·제목·여백으로:** 그룹 H2는 PC·태블릿 20px/모바일 18px, 600·행간 1.4. 주차 제목 18px/17px, 그룹 안 소제목 16px·600. 주요 그룹 간 32px/모바일 24px, 제목→내용 16px, 내부 항목 간 16–24px. `app/zeniel.css`의 `--zf-detail-*` 공통 토큰을 사용한다.
- **반복 정보는 기본 3건:** 주목할 변화·다음 주 일정·현장 요약·활동 타임라인·후속 조치는 3건, 주차 목록은 최근 3개만 기본 표시한다. 전체 건수와 숨은 건수를 알리고 44px 이상의 가벼운 `더 보기`·`접기` 버튼으로 나머지를 확인한다. 최신 해당 주차만 기본 펼침, 과거 주차는 간략 요약을 유지한다. 방문 본문·특이사항은 기록별 `활동 내용` 버튼으로 펼친다. 조건·기간이 바뀌면 펼침을 초기화하며 집계·조회 범위·원본 이동은 유지한다.
- **콘텐츠 그룹은 구분선으로 명확히:** AI 요약·먼저 확인할 사업장·활동 흐름·활동 조회·주차 기록의 시작에는 1px 중립선(`--zf-control-border`)을 둔다. 진단의 주목할 변화/다음 주 일정, 주차 안의 현장 요약/타임라인/후속 조치도 그룹 시작에 1px 선(`--zf-border`)을 둔다. 선→제목 간격은 PC·태블릿 24px/모바일 20px(`--zf-detail-heading-inset`). 주차 경계선도 유지한다. 같은 그룹 안 반복 항목·메타·개별 방문 본문에는 선을 반복하지 않는다. 그림자·중첩 카드·컬러 테두리는 추가하지 않는다.
- **정보의 무게:** 현장·매장명, 핵심 건수·문제 내용은 진한 본문색과 500–600 굵기. 날짜·담당자·출처·집계 설명은 12px 이상 중립색으로 낮춘다. 위험색은 실제 위험에만 사용하고, 현재 미해결 건수를 모든 주차 머리글에 반복하지 않는다. 현재 미해결임을 후속 조치 그룹에서 명시한다.
- **왼쪽 기준선과 안정적인 격자:** 그룹 제목·설명·목록·버튼은 같은 왼쪽 시작점을 쓴다. 아이콘은 별도 고정 칸 또는 `inline-flex`+8px 간격으로 텍스트와 분리한다. 가변 텍스트 칸은 `minmax(0,1fr)`·`min-width:0`, SVG는 축소 금지. 제목·도구·배지는 줄바꿈할 수 있어야 하며 좁은 화면에서 이름·본문을 잘라 숨기지 않는다. 타임라인은 시간순 1열을 유지하며 아래 날짜 축 격자를 따른다. 필터는 PC 5칸→태블릿 2칸→모바일 검색·현장 전체 폭+연월 2칸이다.
- **활동 타임라인의 날짜 축·공간 활용 (2026-10-29):** PC·태블릿은 날짜 64px → 연결축 16px → 가변 본문(`minmax(0,1fr)`)의 시간순 목록이다. 열 간격은 공통 내용 간격 16px, 항목 사이는 24px다. 날짜·시각은 별도 왼쪽 칸, 딥그린 지점과 1px 중립 세로선은 방문 흐름만 연결하고 마지막 항목 아래로 늘리지 않는다. 본문은 현장명·유형/방문자와 방문 목적을 두 열로 나란히 배치하고, 가벼운 `활동 내용` 펼침 버튼을 오른쪽에 두어 빈 폭을 활용한다. 태블릿·모바일에서는 현장·방문자를 위에 두고 목적과 버튼을 아래 한 줄에 배치하며, 모바일은 날짜도 본문 위로 옮겨 좁은 날짜 열을 없앤다. 펼친 원문은 본문 전체 폭을 사용하되 읽기 폭 84ch 안에서 줄바꿈한다. 기본 3건·추가 목록 펼침·원본 이동·실제 방문일/시각 정렬은 유지하며 항목별 가로선·고정 높이·가로 지그재그 배치를 쓰지 않는다. 활동 내용 버튼 열은 공통 토큰 `--zf-detail-timeline-action-width` 128px로 고정하고 펼침·접기에도 같은 폭·높이를 유지한다. 테두리 표면 높이는 `--zf-detail-timeline-action-surface-height` 36px, 실제 조작 영역은 44px다. 펼쳐도 현장·목적·버튼의 위치와 줄바꿈은 고정되고 원문만 아래에 추가된다. 키보드 포커스·aria-expanded/controls와 숨김을 유지한다.
- **상태·접근성:** 펼침 버튼은 `aria-expanded`·`aria-controls`, 연결 콘텐츠의 `hidden`을 함께 관리한다. 접은 내용은 키보드 순서에서 제외한다. 버튼은 같은 위치에서 `접기`로 바뀌어 포커스를 유지한다. 빈 데이터·검색 결과 없음·로딩·오류를 구분하고, 390/820/1280px·200% 확대에서 겹침·가로 넘침·44px 조작 영역을 확인한다.

- 상단에 항목명·식별자·현재 상태를 표시한다. 필드 순서는 입력 폼과 대응시킨다.
- 기본 정보·운영 정보·변경 이력처럼 읽는 목적에 따라 그룹화한다. 단순 데이터 조회를 입력창 모음처럼 표현하지 않는다.
- 주요 수정 버튼은 상단에 배치한다. 삭제는 주요 저장/수정 동작과 시각적으로 분리한다.
- 변경 이력에는 변경 시각·작업자·항목·변경 전후 값을 권한 범위 안에서 제공한다.
- 목록 복귀 시 필터·정렬·페이지·스크롤 위치가 유지되어야 한다.

## 9-B. AI 브리핑·AI 표시 (2026-10-29)

**AI 브리핑 구조:** 대시보드 첫 덩어리(그다음 독려 안내). 늘 보임: 상황 판단 한 줄(판정 칩 + 지금 상황 + 이번 주 할 일, 15px) → **무슨 일이 벌어지고 있나**(옅은 정보 배경, 16px, 가장 눈에 띄게) → 먼저 챙길 곳(`부서 › 매니저 › 매장: 문제`) → 지시 가이드(누구에게 무엇을, 관리자 화면은 부서 대상과 개인 담당자 대상을 함께) → 이행 가이드(번호 1·2·3, 완료 기준). 펼쳐서(`AI 해석 더 보기 · 전할 말 · 다음 주 볼 것 · 반복되는 주제` — 위 카드·아래 목록에 이미 있는 것(지표 숫자·현장별 방문 목록)은 넣지 않는다, 항목 이름 140px | 내용 표 한 형식, 13px, 항목 사이 1px 선, 칸별 배경 없음, 모바일은 이름 위·내용 아래): 보고 주제(현장 링크)·전할 말(바로 아래 직급)·다음 주 볼 것·지표 변화 숫자·근거(보고 n건·판정 m건·모델·시각). 브리핑 문장에 집계 숫자를 쓰지 않는다(숫자는 카드와 펼친 지표 줄에만). 말투는 해요체. 만드는 동안 `조회 범위 데이터 모으기 → 보고 읽고 분석하기 → 브리핑 정리하기` 단계, 경과 초, 4px 진행 막대(보통 10초). 근거: [브리핑 연구](briefing-research.md).

**판정 이름과 경보 표현 (2026-10-29, 근거: 순위표의 지표 집착·게이밍 Keasey 외 2000, Bevan & Hood 2006 / 행동 없는 경보의 둔감화 alarm fatigue 고찰 / 자기 초점 피드백의 역효과 Kluger & DeNisi 1996):** AI 종합 판정 저장값(정상·관찰·주의·위험)은 그대로 두고 화면 이름만 `정상 · 지켜보기 · 조치 필요 · 바로 확인`(`judgment.ts` `LEVEL_LABEL`)으로 보인다. 화면·브리핑 문장에 '위험·리스크·위기' 꼬리표를 쓰지 않는다. 조직 비교 표는 순위 정렬 없이 조직 순서로, 할 일 사실(지연·미등록, 기한 넘긴 조치, 60일+)만 보이고 제목은 `조직별 방문 공백`. 빨강은 기한을 넘긴 사실(기한 초과 조치·지난 필요 방문)에만, `바로 확인`·긴급·담당 미지정·60일+는 앰버, `조치 필요`는 중립.

**브리핑 접기·작성 중 (2026-10-29):** 브리핑 맨 아래 `브리핑 접기`를 누르면 `무슨 일이 벌어지고 있나`만 남고 `브리핑 펼치기`로 되돌린다(이 브라우저에 기억). 브리핑 안 '나쁨' 강조는 앰버로 보이고 AI는 기한 넘긴 사실의 단어 하나에만 쓴다. story는 현황 문장을 되풀이하지 않는다. 작성 중에는 판정 칩·'무슨 일이 벌어지고 있나' 자리에 반짝이 캐릭터(반짝이 3개가 번갈아 반짝, reduced-motion이면 정지) + **`제니에리가 열심히 일하고 있어요`** + 지금 단계 문장(`현장 보고를 모으고 있어요` → `보고를 읽고 무슨 일이 있는지 살피고 있어요` → `브리핑을 정리하고 있어요`) + 단계 표시·경과 초·막대(옅은 정보 배경). 다시 쓰는 동안 이전 내용은 숨긴다.

**한 화면 한 번 (2026-10-29):** 브리핑은 해석·지시, 아래 화면은 기록·원본이다. 같은 목록을 두 번 두지 않는다 — 독려 띠는 숫자 칸만(담당자 칩·도울 방법은 브리핑 지시 가이드), `방문 우선 확인 대상` 표 삭제(브리핑 `먼저 챙길 곳`과 같음), 브리핑 머리의 판정 칩 삭제(독려 띠 `바로 확인 n곳`과 같음), `AI 해석 더 보기`에서 반복 주제 삭제(주간 업무 요약과 같은 보고). 모바일(≤760)은 챙길 곳·지시 가이드가 이름 줄 위·내용 줄 아래, 펼치기 미리보기 숨김.

**브리핑 칸 역할 (2026-10-29 재정립):** 칸마다 역할 하나, 되풀이 금지. 현황=상황 한 문장+잘된 것 한 문장(진전 먼저) / 무슨 일=왜·흐름 / **먼저 챙길 곳과 할 일**=한 목록(대상 이름 → 상태: 핵심 상태 조각만 색, 기한 넘김 앰버·완료 딥그린·미확정 굵게 → 할 일: 받는 사람 이름 딥그린 + 지시 한 문장) / 이행 가이드=그 일을 어떻게(절차·완료 기준) / 전할 말=격려 한 문장+부탁 한 문장(옅은 선택 배경, 늘 보임) / 더 보기=다음 주 확인 신호·근거만. 지시 받는 사람은 구체 이름만('세 팀 담당자' 같은 뭉뚱그림은 버림). 버튼은 `더 보기`·`접기`·`브리핑 접기`·`브리핑 펼치기`만, 설명 꼬리 없음.

**AI 표시(반짝이):** AI가 만들거나 다룬 곳에는 모두 같은 표시 `AiMark`(Sparkles 14px, 딥그린)를 붙인다 — AI 브리핑 패널·칸 제목(AI가 쓴 경우만, 규칙 브리핑은 제외)·판정 칩, AI 등록 창 제목, AI 입력 안내, AI 초안 검토, AI 종합 판정, AI 정리 제안·반영, 목록의 `AI 작성`·`AI 정리 n회` 배지, 결과 목록 `AI 작성` 묶음. 다른 아이콘으로 대신하지 않는다.

## 10-A. 독려 안내(넛지) — 메시지 아이콘·역할별 가이드 (2026-10-29)

방문 등록과 통합 대시보드에서 독려가 페이지 안에 자연스럽게 나온다. 팝업·전면 배너로 가리지 않고, 해당 영역의 흐름 안에 한 덩어리로 놓는다.

**내용 출처 (DC-JUDGMENT):** 문장의 숫자·대상은 공통 현황(`app/platform/status.ts`)의 사실과 저장된 종합 판정에서만 온다. 임계값으로 칭찬·경고를 고르지 않는다. 비교는 본인 지난주와만, 평가어(누락·편중·미이행·소홀) 금지, 잘한 것 먼저 → 다음 행동 하나(계획 4-5-A 표현 원칙).

**위치**
| 화면 | 위치 | 나오는 때 |
|---|---|---|
| 방문 결과 등록(직접·AI) | 저장 직후 시트 안 결과 영역(저장 버튼 자리) | 저장 성공 한 번. 닫기 전까지 유지 |
| 방문 일정 등록 | 저장 직후 같은 자리 | 일정 저장 성공 한 번 |
| 통합 대시보드·잡매니저 홈 | 핵심 지표 바로 아래 한 줄 띠(흰 표면·상단 1px 선) | 화면 진입 때 한 번, 값이 바뀌면 다시 한 번 |

**구성 — 보고 바로 행동 (2026-10-29):** 한 줄 제목 → 큰 숫자 칸(28px·모바일 24px, 최대 4개, 누르면 해당 목록) → 칩(누르면 그 범위로 좁힘) → 다음 방문 + `일정 잡기` 버튼. 숫자는 행동으로 이어지는 것만: `필요 방문 완료 n / 전체`(진행 막대) · `일정 잡을 회차` → 계획 미등록 목록 · `판정 위험`·`판정 주의` → 해당 판정 보고 목록. **0이면 칸을 숨기고**, 숫자를 다시 읊는 문장·"n개 중 m개" 같은 채우기 문장·이번 주 방문 횟수처럼 필요 회차와 헷갈리는 숫자는 쓰지 않는다.

**역할별 내용**
| 역할 | 단위 | 내용 |
|---|---|---|
| 잡매니저 | 본인 담당 | 숫자 칸 + 다음 방문 1곳(코치와 같은 첫 대상)·이유·`일정 잡기`. 저장 직후는 완료 회차가 이전 값→새 값으로 카운트업 |
| 파트장 | 잡매니저 | 숫자 칸 + 일정 잡을 회차가 있는 잡매니저 칩(이름·회차) + `① 이번 주 일정 함께 잡기 ② 동행 방문` |
| 팀장 | 파트 | 숫자 칸 + 파트 칩(개인 이름 없음) + `파트장과 이번 주 일정 확인` |
| 사업부장·관리자 | 팀 | 숫자 칸 + 팀 칩(개인 이름 없음) |

**메시지 아이콘 — 업무 오브젝트 3종 (2026-10-29 갱신):** 첨부된 project-icons SVG의 64×64 캔버스·2.5 단위 라운드 선·단순한 도형과 여백을 참고한다. 얼굴·팔·표정 캐릭터 대신 `joy`(저장 직후·남은 일 없음)는 **체크 문서**, `cheer`(일정 잡을 회차 남음)는 **달력·다음 화살표**, `concern`(저장된 판정 위험 있음)은 **현장·확인 표시**를 쓴다. 기존 mood 선택 로직·문구·숫자는 바꾸지 않는다. `zf-mascot` 클래스는 호환용으로 유지한다.

아이콘은 대시보드 44px·저장 직후 56px, 중립 표면 `--zf-surface-muted`의 둥근 사각 바탕과 딥그린 선·`--zf-selected` 보조 채움으로 통일한다. 첨부의 베이지·세이지·코럴을 새 사이트 색으로 추가하지 않는다. 완료 체크·일정 화살표는 딥그린 채움에 흰 선, 확인 필요 표시는 기존 `--zf-danger`만 소량 사용한다. 아이콘은 SVG 안에 모두 들어오며 밖으로 튀는 느낌표·반짝이를 두지 않는다. 44px에서 읽을 수 있도록 도형과 세부 선을 줄인다. 장식은 `aria-hidden`, 상태 의미는 옆 메시지가 전한다.

머리 줄은 **아이콘 + 평문 제목**(16px·600/모바일15px, 행간1.6·간격12px)으로 정렬한다. 말풍선 테두리·꼬리·튕김을 제거하고 긴 문장은 `minmax(0,1fr)` 안에서 줄바꿈한다. 숫자·칩·다음 대상은 기존처럼 아래 전체 폭을 사용한다. 아이콘의 통통·손 흔들기·기울기·반짝이 애니메이션은 사용하지 않는다. 그라디언트·그림자·글로우도 추가하지 않는다.

**트윈 (한 번 재생, 반복 없음)**
- 메시지 아이콘은 정적으로 표시한다. 저장 직후 숫자의 `+n` 1.1s·진행 막대 끝 반짝임은 기존처럼 한 번만 재생한다.
- 진행 막대: 이전 값 → 새 값 너비 전환 600ms ease-out. 막대 높이 6px, 채움 딥그린, 바탕 `--zf-line` 계열 중립.
- 숫자: 이전 값 → 새 값 카운트업 600ms(정수만). 화면 낭독은 최종 값만 `aria-live="polite"` 한 번.
- 안내 영역: 투명도 0→1 + 위로 4px 이동 240ms. 아이콘 자체의 움직임·말풍선 팝 효과는 없다.
- `prefers-reduced-motion`이면 위 전환을 모두 없애고 최종 상태를 바로 보인다. 같은 값으로 다시 그릴 때는 재생하지 않는다.

**색:** 좋은 신호 딥그린, 사실 숫자는 본문색. 빨강은 판정 `위험`·기한 초과에만, 앰버는 판정 `주의`에만. 독려 띠에 옅은 배경을 새로 만들지 않는다(필요하면 `--zf-info-soft`).

**결과 목록 묶음(2026-10-29):** 방문 결과 화면 상단 묶음은 `AI 작성` + 판정 수준(`위험`·`주의`·`관찰`·`정상`·`미판정`) 건수다. 낱말로 추정한 분류·긴급도는 쓰지 않는다.

### 상태별 행동

- **로딩:** 최종 구조에 맞춘 스켈레톤 또는 진행 표시. 기존 검색 결과 갱신 시 화면을 불필요하게 비우지 않는다.
- **초기 데이터 없음:** 무엇을 등록할 수 있는지 설명하고 권한이 있으면 등록 버튼을 제공한다.
- **검색 결과 없음:** 적용 조건을 보여주고 조건 해제·변경을 돕는다.
- **실패:** 원인 범위, 재시도 방법, 기존 입력/데이터 유지 여부를 안내한다.
- **부분 실패:** 실패한 영역만 표시하고 성공한 결과는 유지한다.
- **읽기 전용/권한 없음:** 이유와 가능한 행동을 설명한다. 권한 제어는 서버에서도 수행한다.
- **세션 만료:** 다시 로그인할 방법과 작성 내용의 보존 가능 여부를 알린다. 무조건 복구된다고 약속하지 않는다.

버튼·입력·선택기에는 default / hover / focus / active / disabled / loading / error 중 해당 상태를 정의한다. 비활성 버튼은 이유를 인접 문구로 설명한다. 클릭할 수 없는 버튼에 달린 hover 툴팁에만 이유를 넣지 않는다.

## 11. 반응형·키보드·접근성

반응형 단계는 아래 세 개로 고정한다(2026-10-28). CSS 미디어 쿼리는 `max-width:760px`, `max-width:1023px`, `min-width:1024px`, 확대 전용 `min-width:1440px`만 쓴다. 화면별로 새 폭(960·1100·1150·1240 등)을 만들지 않는다.

| 단계 | 폭 | 검증 기준 폭 | 기본 동작 |
|---|---|---|---|
| 데스크톱 | 1024px 이상 | 1280px | 사이드바 240px, 필터 한 줄(1280 이상, 1024–1279는 2줄), 대시보드 12열 격자, 핵심 지표 4열 |
| 태블릿 | 761–1023px | 820px | 사이드바 205px 유지, 필터 2줄, 핵심 지표 2×2, 차트·패널 1열, 표는 영역 안 가로 스크롤 |
| 모바일 | 760px 이하 | 390px | 메뉴 드로어 + 하단 탐색, 필터 접기, 전부 1열, 차트 높이 자동, 터치 44px |
| 와이드(선택) | 1440px 이상 | — | 여백·글자만 키운다. 배치는 데스크톱과 같다 |

예외 하나: 조회 조건(필터) 한 줄 배치만 `min-width:1280px`다. 1024–1279px에서는 데스크톱 격자를 유지한 채 필터만 두 줄이다(한 줄로 두면 선택 상자 글자가 잘린다).

- 모바일에서도 핵심 조회·입력·저장이 가능해야 한다. 핵심 열을 무조건 숨기는 방식으로 폭 문제를 해결하지 않는다.
- 행 비교가 중요한 표는 표 형태를 유지한다. 단일 항목 탐색이 주목적인 경우에만 모바일 요약 목록을 병행한다.
- 키보드만으로 메뉴 → 필터 → 결과 → 행 동작 → 페이지 이동을 수행할 수 있게 한다.
- 모든 조작 요소에 2px 이상의 명확한 포커스 표시와 2px 간격을 제공한다. 상태 변화로 포커스를 잃지 않게 한다.
- 모달은 제목 연결, 초기 포커스, 내부 포커스 순환, 닫힌 뒤 원래 위치 복원을 제공한다. 미저장 변경이 있으면 Escape에도 이탈 보호를 적용한다.
- 숨겨진 드로어·메뉴가 Tab 순서에 남지 않도록 한다. 본문 바로가기와 의미 있는 heading 순서를 제공한다.
- 200% 확대에서 조작과 정보가 손실되지 않도록 확인한다. 좁은 폭에서도 페이지 전체가 불필요하게 가로 스크롤되지 않도록 한다.
- 상태 안내는 적절한 live region으로 제공하되 자동 갱신 수치를 계속 낭독하지 않는다.
- 모션은 기본 120–180ms의 짧은 상태 전환에만 사용한다. 예외: 독려 안내(10-A)의 한 번 재생 트윈(최대 600ms). reduced-motion에서는 모든 전환을 없애고 최종 상태를 바로 보인다.

## 12. 운영 문구와 데이터 표기

- 버튼은 구체적인 동사로 쓴다: `조회`, `등록`, `저장`, `승인`, `선택 항목 삭제`. 모호한 `확인`은 줄인다.
- 같은 상태에 다른 이름을 섞지 않는다. 상태 정의·전환 가능 행동·권한을 함께 관리한다.
- 표시 날짜 기본은 `YYYY-MM-DD`, 시각은 `YYYY-MM-DD HH:mm`. 한국 운영 기준은 Asia/Seoul이며 다른 시간대 데이터는 변환 기준을 명시한다.
- 숫자는 `1,234`, 금액은 `1,234,000원`, 비율은 정해진 소수 자릿수를 일관되게 적용한다. 표 헤더에 공통 단위를 명시해 반복을 줄일 수 있다.
- 빈 값은 의미에 따라 `미입력`·`해당 없음`·`집계 중`으로 구분한다.
- 오류 문구는 사용자 행동을 돕는다: `저장하지 못했습니다. 입력 내용은 유지됩니다. 다시 시도해 주세요.` 단, 실제 보존 동작이 있을 때만 이 문구를 사용한다.
- 개인정보 마스킹·열람·다운로드는 역할에 맞춘다. 가려진 값을 CSS로만 숨기지 않는다.

## 14. 화면별 적용 템플릿

### A. 운영 현황

1. `운영 현황` + 화면 목적 + 주요 등록 행동
2. 운영/데모 표시 + 공통 조회 조건
3. 현장/매장 탭 + 핵심 지표 4개 + 차트 6개 + 먼저 확인할 사업장 (6.1-A 구성표). 관리 대상 요약 카드·회차 지표; 방문 이행률만 딥그린 채움
4. 주간 브리핑과 처리 필요 업무로 연결
5. 추가할 차트: `팀별 방문 이행률` 또는 `필요 회차의 현재 상태 구성` 등 1–2개
6. 각 차트 아래 집계 기준·데이터 표·조건을 이어받는 원본 목록

### B. 주차별 업무 기록 (2026-10-29 재정립)

이 화면은 한 질문에만 답한다 — "그 주에 어느 현장에서 무슨 일이 있었나". 해석·지시는 AI 브리핑, 숫자는 지표 카드, 조치는 후속 조치 화면이 맡는다.

1. 대시보드 `주간 업무 기록` 미리보기: 이번 주/지난주 전환 + 현장 한 줄(이름 · 방문 n건 · 최근 날짜 | 가장 최근 보고 한 줄 = 목적 · 활동 첫 문장) 최대 3곳, 누르면 그 현장의 주차 기록
2. 주차별 페이지: 맨 위 주차별 AI 브리핑(주차 선택) → `주차별 업무 기록`(현장 선택 하나)
3. 주차마다 `방문 n건 · 현장 n곳` + 현장별로 묶은 방문 목록: 날짜 · 매장/현장 자체 · 방문자 · 목적 → 활동 한 줄 → `원문` 펼침 → 방문 결과 열기. 현장당 3건 뒤 `n건 더`, 주차 4개 뒤 `이전 주차 n개 더`
4. 두지 않는 것: 발췌 카드, `기한 초과` 칩, 미해결·현장/매장 분해 수, `조치 필요` 필터, 이번 주 먼저 확인할 사업장, 이번 주 활동 흐름, 활동 조회 패널, 현장별 요약 카드, 후속 조치 반복 목록, 주간 집계 기준 안내
5. 모바일(≤760): 미리보기 줄은 이름 위·보고 아래, 방문 목록은 날짜 위·내용 아래

### C. 목록·상세·입력
