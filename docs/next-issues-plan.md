## 1. 운영 판정 백필

**문제:** 운영 화면 AI 브리핑·결과 목록에 `미판정` 칩이 뜬다. 운영 `zf_visits`에 판정(`data.judgment`)이 없어서다. 데모 1,800건만 판정돼 있다.

**준비된 것**
- `scripts/export-visits.mjs` — 운영 방문·조치를 읽기 전용으로 `work/prod-visits.json`(git 제외)에 내려받는다.
- `scripts/judge-reports.mjs <입력> <판정 파일>` — 판정 없는 보고만 대상별 타임라인으로 AI 판정(이름·연락처 미전송).
- `scripts/apply-judgments.mjs <판정 파일>` — 미리보기(대상 건수, 사람이 확정한 판정은 보호) → `--apply`로 한 트랜잭션 적용.

**막힌 것:** 자동 모드가 `SUPABASE_ACCESS_TOKEN`을 쓰는 명령(읽기 쿼리 포함)을 거부한다.

**절차**
1. (사용자) `node --env-file=.env scripts/export-visits.mjs` 직접 실행, 또는 자동 모드 권한에 `node --env-file=.env scripts/*.mjs` 허용 추가
2. `node --env-file=.env scripts/judge-reports.mjs work/prod-visits.json work/prod-judgments.json`
3. `node --env-file=.env scripts/apply-judgments.mjs work/prod-judgments.json` → 미리보기 수치 확인(found/missing/person_confirmed/will_update)
4. `--apply` (사용자 확인 뒤)
5. 운영 화면에서 `미판정` 칩 사라짐·판정 집계 확인, `feature-status.md` 기록

**완료 기준:** 운영 완료 보고 중 판정 없는 건 0, 사람이 확정한 판정 0건 덮어씀, 브리핑 `judged` 집계에 수준 분포 표시.

## 2. 담당자 패턴 판정

**설계(승인됨):** 담당자별 사실 묶음(배정 이력, 필요 회차, 지역별 분포, `필요 시` 근거, 최근 판정)을 AI에 보내 `{findings, excluded, support, selfNote, level}`을 새 테이블 `zf_owner_judgments`에 저장. 지문 같으면 재판정 안 함. 주 1회 또는 상급자 화면 첫 진입 시. 실패 시 사실만 + `미판정`.

**남은 일**
1. 이관: `zf_owner_judgments` (owner_id, period, digest_hash, judgment jsonb, by, at, confirmed_by) + `if not exists`, PGlite 선적용
2. `app/platform/owner-judgment.ts`: 입력 묶음 생성(`status.ts`·`schedule.ts` 재사용) + 스키마 + 정리 함수(`brief-shape.ts`와 같은 방식)
3. 서버 `mode:'owner'` + 백필 스크립트
4. 화면: 잡매니저 홈 `selfNote`, 파트장 담당자별 `level`·`findings`·`support`, 팀장·사업부장은 이름 없이 패턴별 건수
5. 계획 문서 4-5·4-5-A의 임계값 표를 이 구조로 다시 씀(DC-JUDGMENT)

**완료 기준:** 임계값·점수 없음, 화면 라벨은 저장된 판정에서만, `DC-FEEDBACK` 문구 기준 준수.

## 3. 운영 데이터 정리·중복 저장 방지

**문제:** 주차별 업무 기록에 `ㅇ`, `ㅇㄹㅇㄹㅇㄹㅇ` 같은 시험 입력 방문과, 같은 현장·같은 날·같은 본문 보고가 3건 반복 저장된 건이 보인다.

**남은 일**
1. 조사: 시험 입력·중복 보고 목록 추출(읽기 전용, 방문 ID·작성자·시각)
2. 사용자 확인 뒤 삭제 또는 `source='test'` 표시(삭제는 운영 DB 변경 → 승인)
3. 저장 검증: 같은 대상·같은 날·같은 본문(공백 정규화) 저장 시 서버가 거부하고 화면에 "같은 보고가 n분 전에 저장됐어요" 안내 — `mutations.ts`와 `zf_write` 둘 다
4. 본문이 자모만/2자 이하이면 저장 거부("활동 내용을 적어 주세요")

**완료 기준:** 운영 목록에 시험 입력 0건, 동일 보고 재저장 불가, 테스트 `run-platform`·`run-supabase`에 사례 추가.

## 4. 브리핑 생성 시간

**현재:** 운영 계정 4개 11.1–13.7초(추론 none, 출력 ~1,100토큰). 목표 10초 안.

**후보(측정 뒤 결정)**
- 출력 더 줄이기: `watch` 1개, `themes` 0개(화면에서 이미 뺌 → 스키마에서 제거), `steps` 2개
- 입력 줄이기: `reports` 예산 role별 20% 축소 후 품질 비교
- 모델별 속도 비교(`OPENAI_MODEL` 후보 2개, 같은 입력 4회 평균)
- 측정 스크립트: `scripts/brief-sample.mjs`에 시간 기록 줄 복원

**완료 기준:** 4개 직급 평균 ≤10초, 20초 초과 0회(10회 반복).

## 5. 잡매니저 지시에 요청 상대

**문제:** 잡매니저 브리핑 `directive`가 `본인`만 나온다. 파트장에게 요청할 것(동행·재배정)이나 고객사에 확인할 것이 지시로 안 나온다.

**남은 일:** 지시문에 "잡매니저 화면이면 `본인` 외에 `파트장`·`고객사` 대상 지시를 필요할 때 1개 포함" 규칙 추가 → 실제 키로 4회 확인 → 화면에서 `파트장 ›` 누르면 본인 범위 그대로(이동 없음).

## 6. `필요 시` 근거 입력 화면

**현재:** 이관·서버 검증은 적용됨(팀장 이상만, `manual.reason/note/by/at/review`). 화면 입력 칸이 없어 `필요 시`로 바꾸면 저장이 거부된다.

**남은 일:** 현장·매장 등록 창에 주기 `필요 시` 선택 시 사유 선택(5종) + 기타 설명 칸, 재검토일 표시. 재검토일 지난 대상은 상급자 화면에 `주기 다시 확인할 곳 n곳`(status.ts 사실). 지침 8절 갱신.

## 7. 배정 정리 화면

**현재:** 열린 배정이 있는 사용자의 비활성화·팀/파트 이동을 서버가 거부한다(`OPEN_ASSIGNMENTS`). 화면은 오류 문구만 보여 준다.

**남은 일:** 사용자 저장 창에서 거부 시 열린 배정 목록과 `다른 담당자에게 넘기기` 선택을 보여 주고, 넘긴 뒤 저장. 지침 8절 갱신.

## 8. 브리핑 저장본 키

**문제:** `localStorage` 키가 집계 지문뿐이라 같은 PC 다른 사용자가 이전 사용자 범위의 브리핑을 볼 수 있다(계획 4-0).

**남은 일:** 키에 사용자 ID·직급 포함, 로그아웃 시 삭제, `AiBriefSettings` 저장도 같은 방식.

## 9. 검증 범위

**남은 일:** 820px 태블릿에서 대시보드·주차별·등록 창 전수 확인, 200% 확대 확인, `scripts/live-check.mjs`에 820 추가. 결과를 `feature-status.md`에 기록.
