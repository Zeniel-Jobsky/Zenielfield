## 설정 메뉴와 시작 순서

오른쪽 위 아바타 또는 주 메뉴에서 설정을 연다. 운영 모드에는 AI 분석 요소, 관리 도메인, 사용자·조직·권한 관리와 연결 상태가 표시된다. 데모 설정은 구현 범위 안내가 중심이며 운영 계정 발급 화면이 아니다.

1. 시스템 관리자가 활성 관리 도메인을 등록한다.
2. 사용자의 이름·이메일·팀·파트·역할·관리 도메인·활성 상태를 등록한다.
3. 같은 팀·파트의 활성 담당자를 지정해 현장과 산하 매장을 등록한다.
4. 회사 계정 환경에서는 등록된 활성 사용자에게 로그인 수단을 제공한다.

## 역할별 범위

| 역할 | 조회 범위 | 변경 가능 업무 |
| --- | --- | --- |
| 시스템 관리자 | 전체 대상 | 사용자·도메인, 현장·매장·배정, 방문·후속 조치 |
| 사업부장 | 전체 대상 | 업무 데이터 조회 전용 |
| 팀장 | 본인 팀과 도메인 조건 | 범위 내 현장·매장·배정·방문·후속 조치 |
| 파트장 | 본인 팀·파트와 도메인 조건 | 범위 내 현장·매장·배정·방문·후속 조치 |
| 잡매니저 | 공동 배정을 포함한 본인 담당 대상과 도메인 조건 | 본인의 방문·후속 조치. 현장·매장 등록·배정 불가 |

클라이언트 조회 함수는 관리자·사업부장 외 역할의 도메인 목록이 비어 있으면 도메인 필터를 추가하지 않는다. 새 현장 등록에는 활성 도메인과 관리 권한이 필요하므로 빈 목록을 모든 도메인의 등록 권한으로 해석하지 않는다. 실제 서버의 허용 여부는 별도 검증 대상이다.

## 사용자와 비밀번호

사용자 등록은 초대 메일을 자동 발송하지 않으며 등록 폼에서 비밀번호를 받지 않는다. 운영 모드의 시스템 관리자는 로그인 비밀번호 발급·재설정에서 활성 사용자를 선택하고 8–72자 비밀번호를 설정한다. 로그인 계정이 없으면 생성하는 경로가 있다. 회사 계정은 등록 이메일·비밀번호가 기본이고 이메일 링크도 지원한다. 링크는 요청한 브라우저에서 연다. Sites 인증과 구분한다.

계정·비밀번호는 같은 인증 프로젝트의 서버에서 공유된다. 승인된 관리자 업무로만 발급하며 원문을 문서·채팅·커밋에 남기지 않는다. 본인 관리자 권한 해제는 차단한다. 담당 대상이 남은 사용자를 비활성화하거나 팀·파트를 바꾸려면 담당 재배정부터 한다.

근거: [사용자·도메인·비밀번호 화면](../app/platform/users.tsx), [회사 계정 로그인](../app/platform/email-login.tsx). 인증 구성은 [운영 인계](supabase-setup.md)를 참고한다.

## 현장·매장과 관리주기

현장은 활성 도메인이 필수이고 매장은 상위 현장의 도메인·조직을 따른다. 같은 팀·파트의 활성 담당자를 한 명 이상 지정한다. 산하 매장이 있는 현장의 도메인·조직 변경은 별도 이관이 필요하다.

방문 이력이 있는 대상의 주기는 잠긴다. 필요 시 주기의 새 지정·근거 변경은 시스템 관리자·팀장으로 제한하며 근거(기타는 설명 필수)와 재검토일을 기록한다. 파트장의 일반 수정 권한과 구분한다. 계획 취소는 필요 회차를 없애지 않고 완료 기록의 대상을 바꾸는 동작은 허용하지 않는다.

## AI와 운영 확인

AI 분석 요소·생성 결과·브리핑 접힘은 해당 브라우저에 저장되며 공용 설정으로 안내하지 않는다. 판정 표시는 정상·지켜보기·조치 필요·바로 확인이며 내부 저장값은 별개다. 원본 방문과 함께 검토한다.

GPS·주소 검색은 중지되어 대상을 직접 선택한다. 설정 화면의 D1 보존 문구는 실제 자료 이관·접근 가능 여부의 증거가 아니다. 사진 원본 보관·알림·그룹웨어·정식 XLSX는 제공 기능으로 안내하지 않는다.
