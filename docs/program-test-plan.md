# 로컬 프로그램 테스트 계획

기준일: 2026-10-28
대상: http://127.0.0.1:5173/
상태: 계획 수립. 브라우저 접속, 자동 검사, 운영 검증은 미실행.
근거: AGENTS.md, PROJECT_RULE.md, 디자인 지침, package.json, tests/ 실행 파일.
기존 기능 현황의 통과 횟수는 과거 기록이며 이번 실행 결과가 아니다.

## 목표와 준비

방문계획 → 방문결과 → 후속 조치 → 브리핑의 정확성과 역할별 데이터 격리를 최우선으로 확인한다.
실행 전 커밋·작업 트리·푸터 빌드 정보, 브라우저 버전, 인증 제공자, 데이터 모드를 기록한다.
데모 및 격리된 테스트 데이터로 시작한다. 로컬 주소라도 공용 Supabase에 연결될 수 있다.
운영 DB 쓰기·계정 발급·Edge 배포는 기존 규칙에 따라 별도 승인 대상이다.
기존 계정이 없으면 인증 검증은 차단으로 기록하며 임의로 계정을 만들지 않는다.

역할 이름과 허용 범위는 실행 전 코드 및 승인된 권한표로 확정한다.

회차 인정 방식은 model 규칙에 맞춰 표본을 구성하며 방문 건수를 회차로 대체하지 않는다.

## 자동 검사와 순서

1. 환경·데이터 연결 확인 및 T01~T04 진입·권한 점검.
2. npm run typecheck, npm test 실행. 현재 npm test는 platform·briefing·diagnosis·supabase·logic·ui-metrics 6개 묶음이다.
3. 위치·시드·인증 추가 검증: tests/run-geo.mjs, run-seed.mjs, run-cloudflare-auth.mjs, run-cloudflare-supabase.mjs를 node로 실행한다. 실행 전 외부 연결·쓰기 여부를 점검한다.
4. T05~T16 및 반응형·접근성 수동 검증.
5. npm run build 실행 및 빌드 산출물 확인. 패치 버전 자동 증가를 기록하며 검증용으로 생략할 때는 PowerShell에서 NO_BUMP=1 환경변수를 임시 설정하고 복구한다.
6. 결함 수정 후 실패 사례와 영향 범위를 재검증한다. UI 수정은 지침·두 룰 갱신 및 실제 화면 재검증을 동반한다.

API·인증 모의 테스트 통과는 실제 Supabase 로그인·권한 검증을 대신하지 않는다.
초기 실행 예상은 환경 준비 0.5일, 업무·권한 1일, 화면·회귀 0.5일이다. 수정 시간과 계정 대기는 별도다.

## 완료와 증적

P0 전부 통과, 데이터 유실·권한 누출·집계 오류 0건을 필수로 한다.
미해결 P1은 영향·우회 방법·출시 허용 판단을 기록한다. 차단·미실행은 통과로 세지 않는다.
각 결과는 ID / 환경·역할 / 사전 데이터 / 절차 / 기대·실제 / 통과·실패·차단·미실행 / 증적 / 결함 ID로 기록한다.
스크린샷·네트워크 증적은 개인정보·토큰을 제거한다. 최종 보고에는 커밋·빌드·화면 크기·검사 결과를 포함한다.
