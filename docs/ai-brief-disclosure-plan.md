# AI 브리핑 정보 위계와 단계적 공개

2026-10-28 · Codex · 디자인 개선 · 로컬 검증

---

> 💡 **핵심** — 기본 화면은 큰 요약과 첫 제안에 집중한다. 보고 내용은 현장 목록 → 현장별 근거 순으로 펼쳐 본다.

## 기준과 구현

- 방향: 읽기 부담이 적은 업무 브리핑. 요약·제안의 크기와 여백을 중심으로 구성한다.
- 타이포: 요약 PC·태블릿 20px/모바일 18px, 제안 17px/16px, 행간 1.7. 레이블 14px/600.
- 구성: PC 요약·제안 2열, 태블릿·모바일 1열. 상태·대체 안내만 기본으로 남기고 상세 지표·흐름·격려·메타는 접는다.
- 색·표면: 기존 흰 표면·중립 경계·텍스트 토큰을 재사용한다. 큰 컬러 카드나 새 장식은 추가하지 않는다.
- 버튼: 보고 내용과 브리핑 상세 진입은 흰 보조 버튼, 6px 모서리·44px 조작 영역. hover·active·focus·펼침 상태를 구분한다.
- 보고 목록: 현장명·주제명만 먼저 보인다. 각 현장의 `더 보기`로 주제 요약·상태·근거를 공개한다. 선은 현장 사이에만 둔다.
- 공통 근거: 여러 현장에 연결된 주제는 공통임을 표시한다. 현장 미지정 주제도 보존하며 AI 내용·대상·근거를 임의로 바꾸지 않는다.
- 동작: 별도 모션 없이 즉시 펼친다. 숨긴 콘텐츠는 Tab 순서에서 제외하고 버튼의 expanded/controls 연결과 포커스를 유지한다. 조건·역할·기간 변경 시 접는다.

`app/platform/ai-brief.tsx`의 표시 컴포넌트를 분리했다. 자동 작성·캐시·집계·요청·응답 형식·개인정보 처리는 그대로이며, 규칙 대체 이유와 낮은 확신은 기본 화면에 남는다. 대표 제안은 기존 첫 판단을 그대로 보여 주고 상세에서 중복하지 않는다. 첫 판단이 없으면 기존 다음 확인 항목을 사용하고, 둘 다 없으면 추가 제안 없음을 알린다.

## 화면 진단

변경 전 주요 문제는 ① 요약·제안 위계가 약함 ② 보고 주제·근거가 기본으로 모두 보임 ③ 중첩된 목록마다 선이 들어감 ④ 텍스트 형태의 긴 펼침 문구 ⑤ 흐름·격려·지표·메타까지 같은 화면에 노출됨이었다.
